# v0.4 设计：K 循环与累加器（受限迭代）

状态：定稿并已实现（2026-08-24，含同日评审修订 §13）。前置：v0.1（`type-system.md`）、
v0.2 预览与 matmul fragment、v0.3 strides（`v0.3-strides.md`）。本文不修改已冻结的
dtype / strides / 寻址语义；新增的只有**迭代**与一条新 layout 律。验收（§8）全数
通过：任意 K 的 matmul（K ∈ {0, 1, 40, 63, 64, 65, 130, 512, 4096}，含非 BK 倍数
与零迭代恒等式）在 interpreter 与 GPU 双路径与 torch.matmul 对拍一致；既有六份
黄金逐字节不变（纯增量）。

---

## 0. 动机：直线 SSA 遇上迭代

v0.1 起的 kernel 体是**直线代码**（straight-line SSA）：名字单赋值、指令扁平、
一条路径。matmul fragment 只算了**一个 K 块**（K = BK），真实的 matmul 必须沿 K
维循环累加——`acc += dot(x_k, y_k)`。这暴露的不是缺一个语法，而是缺一条
**跨迭代的值通道**：

- 直接放开 Python 式自由重赋值（Triton 风）会瓦解 E14 单赋值纪律与 TIR 的
  SSA 不变量——类型系统对"每次迭代里 acc 是什么类型"将无从谈起。
- 完全 SSA 化需要 φ 节点与不动点类型推导——v0.4 不需要那么强。

本设计取**受限累加器**：迭代间唯一的可变状态是**显式播种的累加器**，其余代码
保持直线单赋值。Triton 里 loop-carried variable 的机制照用，但 Tila 侧把它
类型化、围栏化。

**不变量（本设计的全部内容围绕它；评审 §3 修正表述）**：

> 循环体是"直线代码 + 受限累加"：名字在循环内仍然单赋值；**除编译器生成的
> 归纳变量外，循环间唯一允许的用户可见 loop-carried state 是显式播种的累加器
> φ**；累加器必须由 `tila.zeros` 播种、在体内只能作 `+=` 的更新目标。

（归纳变量 `k0` 也是 loop-carried state，但它是 compiler-generated、非用户可见
的携带——把它从陈述中排除后，将来 split-K / reduction / 嵌套循环下这句话继续
成立。）

由此得到一条语言哲学：

> **迭代是显式的，可变性是被围栏的。**（mutation is fenced into a named,
> zeros-seeded accumulator list——不是散落在循环体任意赋值里。）

验收场景：**任意 K 的完整 matmul**（K 不是 BK 的倍数、K 超大），
interpreter / GPU 双路径对 torch.matmul 差分。

## 1. 表面语法

目标程序（全 K matmul；`a/b/c` 注解与 v0.3 strides 完全一致）：

```python
import tila


@tila.jit
def matmul(
    a: tila.Tensor[tila.float16, M, K],
    b: tila.Tensor[tila.float16, K, N, (sb0, sb1)],
    c: tila.Tensor[tila.float16, M, N],
    BM: tila.constexpr = 64,
    BN: tila.constexpr = 128,
    BK: tila.constexpr = 64,
):
    pid_m = tila.program_id(0)
    pid_n = tila.program_id(1)
    rm2 = tila.expand_dim(pid_m * BM + tila.arange(0, BM), 1)    # (BM, 1)
    rn2 = tila.expand_dim(pid_n * BN + tila.arange(0, BN), 0)    # (1, BN)
    rk2 = tila.expand_dim(tila.arange(0, BK), 1)                 # (BK, 1)  ← a 的 K 轴
    rk3 = tila.expand_dim(tila.arange(0, BK), 0)                 # (1, BK)  ← b 的 K 轴
    c_m = (rm2 < M) & (rn2 < N)

    acc = tila.zeros((BM, BN), tila.float32)
    for k0 in tila.range(0, K, BK):
        rka = rk2 + k0
        rkb = rk3 + k0
        x = tila.load(a, (rm2, rka), mask=(rm2 < M) & (rka < K), other=0.0)
        y = tila.load(b, (rkb, rn2), mask=(rkb < K) & (rn2 < N), other=0.0)
        acc += tila.dot(x, y)

    c16 = tila.cast(acc, tila.float16)
    tila.store(c, (rm2, rn2), c16, mask=c_m)
```

### 1.1 for 与 tila.range

```python
for k0 in tila.range(0, K, BK):     # start 必须是字面量 0；end 是运行期 i32 标量；step 是编译期常量 ≥ 1
    ...                             # 循环体：普通语句子集 + acc += tile
```

- **`tila.range` 是循环专属 intrinsic**，不是值：只允许出现在 `for ... in` 的
  iterable 位置（其它位置 → E20 RangePosition）。它与 `tila.arange`（tile
  构造器、extent 必须是 2 的幂 constexpr）语义无关、名字刻意对立。
- **start 恒为字面量 0**（与 arange 同款规范化：只留一个自由度）。
- **end 是运行期标量表达式**：符号维名（`K`）、标量算术（`K - BK`）、整数字面量
  都可；必须是 `Scalar(i32)`（Tile → E20 RangeForm）。trip count 动态。
- **step 是编译期常量**（INT 字面量或 constexpr 名；复用 arange 边界的
  ConstExpr 求值器），特化值 ≥ 1，否则 E20 RangeForm。运行期 step 不进 v0.4。
- 循环变量 `k0 : Scalar(i32)`，运行期值 0, step, 2·step, …，`< end`。
  体内参与 R4 标量广播（`rk2 + k0` 的 layout 走 L2，一切照旧）。
- `for` 只允许出现在 kernel 体**顶层**；循环体内再出现 `for` → E20 NestedLoop
  （嵌套循环是独立设计，不是本文缺项）。`for ... else` → E11（转换期）。
- 顶层允许**多个顺序 for**，也允许第二个循环继续 `+=` 同一累加器（其类型此时
  已是 Mma，走 equiv 分支，规则自然成立——多段累加无需新机制）。

### 1.2 tila.zeros：常量播种

```python
acc = tila.zeros((BM, BN), tila.float32)     # shape 元组：INT 字面量或 constexpr 名；dtype 引用
```

- shape 是**位置元组**（与坐标元组同款排版理由：Python 下标/调用不支持所需
  形态的富语法；`(BM, BN)` 是 `ast.Tuple`，结构性无歧义）；每项 INT 字面量或
  constexpr 名——**必须是静态量**（运行期符号维 → E20 ZerosForm：累加器形状
  参与类型等价判定，动态形状的 φ 无从谈起）。
- rank ≤ 2（沿用房 rank 上限；≥ 3 → E20 ZerosForm）。dtype 走 DTypeRef 位置
  （`tila.cast` 第二实参同款解析）；bool → E20 ZerosForm（掩码来自比较，
  与 Buffer 元素 dtype 同一禁令）；其余 16 种 dtype 任意。
- **zeros 是新 layout 种子**（§2.1），不是 `arange * 0` 之类的糖——来源即语义。

### 1.3 `+=`：受限累加器纪律

```python
acc += tila.dot(x, y)          # 体内唯一合法的"重赋值"形态
```

- **`+=` 是累加器的 primitive update（reduction update），不是赋值的缩写**
  （评审 §1/§20 采纳）：表面语义**直接定义为**
  `acc⁺ = acc_current ⊕ t`——编译器隐式以累加器当前状态作为更新的 LHS
  state，这个**内部状态读不属于表面层的累加器读**。`+=` 因此**不是**
  `acc = acc + t` 的语法糖；它与下条 AccumRead 禁令不矛盾，恰恰因为读
  旧值这件事在表面上从未发生。⊕ 目前只有 `'+'`；reduction update 家族
  （max/min/…）沿同一形态泛化（§9 预留）。
- **只有 `+=`**（`-=` `*=` `/=` 等 → E20，转换期拦截）；只有**累加器**可作
  更新目标；`+=` 只在循环体内合法（体外 → E20 AccumForm）。
- **累加器的认定**：循环外由 `acc = tila.zeros(Σ, dt)` 播种绑定。非 zeros
  播种的名字（含循环体内定义的名字、sym / constexpr / buffer / 标量参数）
  作 `+=` 左部 → E20 AccumForm。
- **表面层禁读**：`acc` 不得作为**普通表达式值**出现在体内任何位置（含
  `+=` 右部、运算、store 实参）→ E20 AccumRead——"an accumulator may not
  be used as an ordinary expression value inside the loop; the only
  permitted use is the left-hand target of `+=`"。这是 φ 类型化的前提
  （§2.3），也是围栏的执行形态。**循环结束后读 `acc` 合法**——绑定的是
  循环出口值。
- dtype 严格相等（E02）、shape **严格同形**（E03；不广播累加——
  `acc (BM,BN) += t (1,BN)` 非法，要 `expand_dim`）；dtype 须通过 `'+'`
  能力门（fp8 → E16，storage-only）；layout 见 §2.1。

**被拒的替代设计**：

| 方案 | 拒绝理由 |
|---|---|
| Triton 式自由重赋值（体内任意 `x = x + 1`，loop-carried 自动推断） | E14 单赋值与 TIR SSA 不变量整体让位；"哪些名字跨迭代"从声明变推断，与 MemoryLayout 的 declarative 哲学同款问题；φ 类型化退化为不动点迭代 |
| while / break / continue | 动态 trip count 与围栏外控制流；tiling 的迭代形态是 range-for，先服务它 |
| 累加器由 load 播种（`acc = tila.load(...)` 后 `+=`） | φ 需要 equiv(L_entry, L_exit) 的真正不动点推导（entry 不再是单位元）；v0.4 的 matmul 只需要 zeros 播种，推迟（§9） |
| 标量累加器（`s += k0`） | 同上，且标量无 layout 故事却要同一套 φ 机制；收益小 |
| `acc = acc + dot(...)` 普通赋值 spelling | 把 primitive update 伪装成普通赋值（且与单赋值冲突，E14）；`+=` 是显式的 update 意图标记——语义上二者并不等价（前者表面层读了 acc，后者没有） |
| 体内允许读累加器 | 读到的是入口类型还是出口类型？前者错、后者要前向 typing。围栏化（禁读）让 φ 类型 = 出口类型一行写完 |
| loop-local 名字出循环可见（Python 泄漏语义） | 零迭代时未定义值；作用域结束是唯一干净语义（出循环引用 → E20 LoopScope） |

## 2. 类型层

### 2.1 ZeroSeed：distinguished 种子态与律 L7（`type-system.md` §3.2 的 v0.4 增补；评审 §2/§11 折中采纳）

```
DistLayout ::= … | Zeros(Σ)        # distinguished 种子态（非普通 term，见下）
```

**`Zeros(Σ)` 不是一种普通 DistLayout，而是嵌在 join 关系里的 distinguished
accumulator seed state**（评审 §2 的概念修正，按其折中形态采纳）：

- **语义**：全同元素 tile 的分布**不可观测**（任何坐标解释下值都相同）。
  `Zeros(Σ)` 记录的是"**分布未定**"这一状态——不是"分布是一种叫 Zeros 的
  布局"。一个全零 tile 还没有获得具体的计算分布。
- **因此它按定义被排除在 equiv 之外**（`equiv(Zeros, L)` 仅在 L 同为 Zeros
  时成立——两个"未定"相等），却以 **join 单位元**的身份参与合并：

```
(L7)  ZeroSeed ⊕ L ≡ L        （Σ 同形；对称）
```

  L7 读作**种子物化规则**：未定分布 ⊕ 具体分布 = 具体分布。"不能参与普通
  equiv、却参与一种特殊的 join"正是 distinguished 态的签名性质。
- **为什么 term 仍住在 `TileType.layout` 里**（强形式重构的拒绝理由，§13）：
  `z = tila.zeros(...)` 是合法的 Tile 值（可 store、可 Zeros⊕Zeros 运算），
  它的类型必须携带种子标记——term 的**载体**没有第二个住处；改变的是它的
  **地位**（equiv 排除、join 单位元、R14 广播路径不落律——§9 保持部分性诚实）。
- **checker 的累加器检查以状态机表述**（评审 §10/§11；实现即 carried 链）：

```
AccumulatorState:
    Seed(shape, dtype)              # zeros 播种，分布未定
      ↓ 首次 acc += t                # L7 物化
    Materialized(L)                 # 采纳 t 的分布
      ↓ 其后 acc += t'               # equiv(L, L')（E05）
    Materialized(L)                 # 分布锁定
```

**R17 zeros**：

```
Γ ⊢ sᵢ 静态（INT | constexpr 名，特化值 v(sᵢ)）   dt ≠ bool   rank ≤ 2
──────────────────────────────────────────────────────────────────────
Γ ⊢ tila.zeros((s₀,…,s_{r−1}), dt) : Tile[dt, (Const(v(sᵢ)),…), Zeros((v(sᵢ),…))]
```

### 2.2 R18 for / tila.range

```
Γ ⊢ e : Scalar(i32)    step ∈ ConstExpr，特化值 ≥ 1    start ≡ 字面量 0    B 在 §2.4 作用域下良式
────────────────────────────────────────────────────────────────────────────────────────
Γ ⊢ for x in tila.range(0, e, step): B    绑定  x : Scalar(i32)
```

体内既有规则全部原样适用（load/store/dot/cast/比较/广播）——循环不是新语义，
是新**作用域**（§2.4）。`program_id` 在体内引用合法（值跨迭代不变）。

两条注记（评审 §4/§6 采纳）：

- **end 里的 `K` 是维符号的运行期物化**：符号维有双重视图——type-level 是
  DimSymbol（注解 `Tensor[f16, M, K]`），value-level 在体内引用时物化为
  `Scalar(i32)`（`language-spec.md` §7 的 elaboration 规则）。
  `tila.range(0, K, BK)` 与 `offs < K` 依据的是同一条规则。
- **start ≡ 字面量 0 是 syntactic restriction，不是 semantic
  impossibility**：TIR 的 `TFor` 省略 start 字段正是该约束的 IR 投影；将来
  split-K / 相位循环需要 `TFor(start, end, step)` 时加回字段即可，不破 IR
  （§9）。

### 2.3 R19 累加与 φ 类型

```
acc 在循环外由 R17 播种 : Tile[dt, Σ, Zeros(Σ)]        Γ, x ⊢ t : Tile[dt, Σ, L_t]
体内语句  acc += t ：
  dtype 相等（E02）   shape 严格同形（E03）
  L_acc ≡ Zeros  →  结果 layout = normalize(L_t)（L7：Zeros ⊕ L_t ≡ L_t）
  否则            →  equiv(L_acc, L_t)（E05），结果 = L_acc
────────────────────────────────────────────────────────────────────────────────
φ(acc) : Tile[dt, Σ, L_exit]        循环后  acc : Tile[dt, Σ, L_exit]
```

- **φ 类型 = 体内最终类型**。这个"一行写完"依赖两个围栏：种子是 ZeroSeed
  （L7 单位元使入口不需要不动点）＋体内禁读（φ 没有其它消费者，最终类型
  良定义）。
- **φ 类型不变量（评审 §13 的精确形态）**：`type(φ) = type(back)`；`pre`
  操作数的类型在 v0.4 恒为 zeros 种子（join 单位元）——入口值在任何分布
  解释下与 φ 类型兼容（L7）。评审原式 `type(pre) = type(φ) = type(back)`
  在种子是单位元时恰恰不成立（那是 L7 的用武之地）；若将来放开非 zeros
  播种，本不变量升级为 `equiv(L_pre, L_exit)` 前提。TPhi 自身携带
  tila_type，printer 无需按 id 回查。
- 体内多次 `acc += t₁ / += t₂`：第一条走 L7 出种子，其后走 equiv——与
  R5 的纪律完全同构（join 链单调）。**状态机贯穿多个循环**：第二循环的
  入口已是 `Materialized(L)`（如 Mma），走 equiv 分支——多段累加无需新机制。
- **不发明新布局机制**：除 L7 外全部复用现有律与 equiv。

### 2.4 作用域规则（循环的唯一新名词法）

体内可见：buffers / syms / constexprs / 标量参数 / **外层 locals（读）** /
`k0`（绑定）/ 循环局部（体内新绑定，单赋值照旧 E14）。三条围栏：

1. **外层名只读**：体内 `x = <expr>` 的目标撞外层名 → E14（既有单赋值，
   无新码）。
2. **累加器读写纪律**：§1.3（E20 AccumForm / AccumRead）。
3. **循环局部不出循环**：体内绑定的名字（含 `k0`）在循环后不可见 →
   E20 LoopScope。循环后新增可见绑定 = 被本循环 `+=` 的累加器（出口值）。

## 3. TIR

```
TZeros: shape: tuple[ConstExpr, …], dtype: str
TFor:   end: str, step: ConstExpr, body: tuple[TOp, …]      # id = 归纳变量；start 隐含字面量 0
TPhi:   pre: str, back: str                                  # id = φ 名（acc.loop）；body 顶部
```

- **TIR 从扁平变为"一层可嵌套"**：`TKernel.ops` 里出现 `TFor` 时其 `body`
  是嵌套指令序列；v0.4 不允许嵌套 TFor（E20 在 checker 拦，TIR 结构不设防）。
- **TPhi 是 TIR 唯一允许前向引用的指令**：`back` 指向同 body 内后文定义的
  最后一个 `+=` 结果——SSA φ 的标准形态，dump 与不变量文档都显式记这一条。
  它是 **structured loop-carried φ**（评审 §12 意图采纳、改名不做）：当前
  IR 无一般 CFG（控制流倾向 select，§9），φ 在 TIR 中无歧义；若将来引入
  CFG φ，那是另行设计的更一般课题。
- **id 命名**：种子沿用赋值名（`acc`）；φ 为 `acc.loop`；体内第 i 个 `+=`
  结果为 `acc.next`、`acc.next.2`、…（`.loop/.next` 后缀不与用户名冲突——
  标识符不含 `.`）。三者的 `src_name` 同为 `acc`（发射名统一）。
  无 `+=` 的累加器不发射 φ（无携带）；`k0` 即 TFor 的 id/src_name。
- **`+=` 的 IR 形态是普通 `add`**：`%acc.next = add %acc.loop %t9`。累加语义
  完全由 TFor/TPhi 结构承载，opcode 集不膨胀。
- dump（canonical，缩进 2 空格；layout 定义行随 namer 递归注册）：

```
func @matmul(a: Buffer<f16,(M,K)>, b: Buffer<f16,(K,N),strides=(sb0,sb1)>, c: Buffer<f16,(M,N)>, …)
L0 = identity(64)
L1 = identity(128)
L2 = product(broadcast(L0, 1),broadcast(L1, 0))
L3 = mma(64,128,64)
L4 = zeros(64,128)
…
%acc = zeros (64,128) f32 : Tile[f32,(64,128),L4] [#acc]
%k0 = for 0 %K BK : Scalar(i32) [#k0]
  %acc.loop = phi %acc %acc.next : Tile[f32,(64,128),L3] [#acc]
  %rka = add %rk2 %k0 : Tile[i32,(64,1),L0] [#rka]
  %x = load %p2 mask=%m0 other=%t3 : Tile[f16,(64,64),L2] [#x]
  …
  %acc.next = add %acc.loop %t9 : Tile[f32,(64,128),L3] [#acc]
%c16 = cast %acc.next f16 : Tile<f16,(64,128),L3] [#c16]
store %p4 %c16 mask=%m1
return
```

- `_finalize_ids` / printer 的操作数遍历递归进 TFor.body 并覆盖 TPhi
  （机械扩展；# 临时 id 重写跨层一致）。

## 4. Triton lowering

### 4.1 kernel 体（`triton-lowering.md` §5 的 v0.4 增补）

```
acc = tl.zeros((BM, BN), dtype=tl.float32)        # 种子：shape 按 ConstExpr 渲染（名字或字面量）
for k0 in range(0, K, BK):                        # range 三件套：0、end 操作数、step ConstExpr
    rka = rk2 + k0
    x = tl.load(a + (rm2 * K + rka), mask=(rm2 < M) & (rka < K), other=0.0)
    y = tl.load(b + (rkb * sb0 + rn2 * sb1), mask=(rkb < K) & (rn2 < N), other=0.0)
    acc = acc + tl.dot(x, y)                      # φ 不发射；add 以源名 acc 渲染
c16 = acc.to(tl.float16)
tl.store(c + (rm2 * N + rn2), c16, mask=(rm2 < M) & (rn2 < N))
```

- **缩进**：body_lines 递归渲染，每层 +4 空格；TPhi 与合成引用一样跳过发射。
- **loop-carried 由 Triton 接管**：种子在循环前物化、体内以同名 `acc` 读写，
  Triton 自行做它的 SSA；Tila 侧的 φ/next 命名只服务 TIR 可读性。跨迭代类型
  稳定（f32 (BM,BN) 进出一致）由 R19 的严格 dtype/shape 检查保证。
- **匿名内联照旧**，但循环体引用外部值时按定义点物化（use_count 全局统计，
  跨层引用计入）；纯体内匿名单次使用仍在体内内联——无新机制。
- addptr/load/store/cast 的发射规则与 v0.3 完全一致（循环不改任何既有发射）。

### 4.2 launcher：零改动

循环不产生新参数类别、不改 grid。K 轴不是 program_id 轴——launch analysis
只在 `program_id` 上做模式识别（§6），`k0` 不参与。

## 5. Interpreter

- **动态执行**：`TFor` 求值 = `k = 0; while k < v(end): 绑定 var；执行 body；
  k += v(step)`。φ 链：迭代开始时 `vals[phi] = 当前携带值`（首轮 = 种子），
  迭代结束 `携带值 = vals[back]`。
- **零迭代回退**：trip count 为 0 时循环后 `acc` 的出口 id 未被写——回填
  种子值（`vals.setdefault(back, vals[pre])`）。Triton 的 loop-carried 语义
  同款，双路径一致。
- 体内既有 op 求值全部原样（load/store/dot/arith…）；TAddPtr 的惰性
  `(base, coords)` 形态不变。
- `+=` 是普通 add：numpy 语义天然正确。

## 6. LaunchPlan：零扩展，analysis 递归扫描

`plan_launch` 的 pattern 识别（`pid * CE + arange`、`offs < dim`）在**拍平的
op 序列**上进行——v0.4 起 flatten 时递归展开 TFor.body（tiling idiom 可以在
循环体内；本例在外，但分析不依赖位置）。LaunchPlan 结构不变。

## 7. 诊断：E20 LoopForm（新增）

subcode 机制与 E19 同款（渲染显示 `E20`；`TilaError.subcode` 供测试矩阵）。

| 场景 | subcode | 消息要点 |
|---|---|---|
| `for` 的 iterable 不是 `tila.range(...)` 调用（含裸 `range`、名字、属性） | NotRange | "the only iterable is tila.range(0, end, step)" |
| tila.range 实参数量 ≠ 3、start 非字面量 0、step 非 ConstExpr / < 1、end 非 Scalar(i32)、带 kwargs | RangeForm | 指明三件套形态 |
| `tila.range` 出现在非 iterable 位置（赋值右部等） | RangePosition | "tila.range may only appear as the iterable of a for loop" |
| 循环体内出现 `for` | NestedLoop | "nested loops are out of scope in v0.4" |
| zeros：shape 非位置元组 / 项非 INT·constexpr / rank ≥ 3 / dtype 缺失或 bool / 实参数量 | ZerosForm | "shape must be a tuple of integer literals or constexpr names" |
| `+=` 体外；`-=` 等其它增强赋值；左部非 zeros 播种累加器 | AccumForm | "only '+=' on a tila.zeros-seeded accumulator inside a loop is legal" |
| 累加器在体内作为普通表达式值（含 += 右部、store 实参） | AccumRead | "an accumulator may not be used as an ordinary expression value inside the loop; the only permitted use is the left-hand target of '+=' (read it after the loop)" |
| 循环局部名（含 k0）在循环后被引用 | LoopScope | "loop-local names are not visible after the loop" |

分工纪律：dtype/shape/layout 链仍走 E02/E03/E05；单赋值冲突仍走 E14；E20 只管
**循环形态与围栏**（"E07 不做垃圾桶"原则同款适用）。转换期可判定的（非 `+=`
增强赋值、for-else、非 range iterable）在 desugar 抛，其余在 checker。

## 8. 测试计划

1. **黄金**：新增 `matmul_loop`（TIR + Triton）两份快照；**既有六份黄金逐字节
   不变**（无循环的 kernel 不经过任何新路径——v0.4 是纯增量）。
2. **E20 矩阵**：§7 逐 subcode 一测（断言 `TilaError.subcode`）；外加
   `+=` dtype 失配（E02）、shape 广播累加（E03）、Mma·非 Mma equiv（E05）、
   体重绑定（E14 既有）——证明 E20 不越权。
3. **L7 单元**：normalize 落律（join(Zeros, Mma) → Mma、对称、Zeros+Zeros）、
   equiv(Zeros, Mma) = False、strides_of 不受影响。
4. **差分（验收主场）**：全 K matmul，interpreter 与 GPU 双路径 vs
   `torch.matmul`：
   - **K 非倍数**：K ∈ {1, 40, 63, 64, 65, 512, 4096}（K < BK 单迭代重掩码、
     K=4096 大循环）；M=100、N=140 沿用非倍数 + 边界掩码；
   - **零迭代恒等式**（评审 §14/§15 采纳）：K=0 时 `Loop(0, seed, F) = seed`
     且 `C = A·B = 0`——既是循环正确性测试也是 identity 测试（CPU + GPU；
     size-0 数组的 RowMajor 契约空真，§12）；
   - **b 非连续**：转置 / padded（v0.3 strides 正交性回归——循环不改内存语义）；
   - **多段累加**：两个顺序 for 累加同一 acc（equiv 分支）。
5. **loop-carried 语义等价（评审 §16 采纳）**：`lower(LoopPhi) = Triton
   loop-carried assignment`——Tila 的 φ 与 Triton 的同名变量携带不是逐字节
   对应而是语义等价；验收 = 同一 TIR 的 interpreter/GPU 差分（黄金只钉文本，
   Triton 内部对 for 的 lowering 变化不影响本验收）。
6. **launcher 单元**：无新断言——回归既有即可。

## 9. 范围外（显式不做）

| 项 | 理由 |
|---|---|
| 嵌套循环 / while / break / continue | 嵌套是独立设计（多维 tile 循环、split-K 都可能要它）；while 的动态 trip 与围栏外控制流先不碰。**一般 CFG 亦非目标**：将来即使需要条件，也先考虑 select 而非 if（评审 §21 背书） |
| 非 zeros 播种的 carried 值（load 播种 / 标量累加器） | φ 需要 equiv(L_entry, L_exit) 不动点推导；v0.4 用 L7 单位元免掉它，收益立即、代价为零 |
| 体内读累加器 | 需要出口类型前向 typing；围栏化后 φ 类型一行写完（§2.3） |
| 广播累加（`+=` shape 严格同形） | 累加是赋值语义不是运算语义；隐式广播累加会掩盖 shape 错字（与"无隐式收窄"同款哲学） |
| `+=` 的 ⊕ 扩充（max/min 等 reduction update） | 表面形态已预留（primitive update，§1.3）；家族扩充随归约内建一起设计 |
| `tila.range` 的 start ≠ 0 | **syntactic restriction 而非 semantic impossibility**（评审 §6）：将来 split-K / 相位循环需要时，`TFor` 加回 start 字段即可，不破 IR |
| `ProductL(Zeros, L)` 的 L7 同余 | 广播路径与种子态的交互暂不落律；保持部分性诚实（§2.1） |
| unrolling / `tl.range(num_stages=…)` / 循环变换 | 优化与流水线属 lowering 策略层（launch analysis 的未来挂点），v0.4 只发射朴素 range |
| loop-carried Tile 以外的类型 | 全部推迟（表内第一行已述） |
| `for` 的 else 子句、迭代器协议 | Python 形态，无 GPU 语义对应（转换期 E11） |

## 12. 实现记录（落地期裁定）

- **step 非 ConstExpr 的码归属**：`eval_constexpr` 天然抛 E10；为守 §7 的
  "step 非 ConstExpr → RangeForm" 表格，check_for 捕获后转 E20 RangeForm
  （消息更具体，语义相同）。
- **累加器认定 = zeros 播种 ∧ 被累加**：kernel 全体（含循环体）预扫描 `+=`
  目标名集合；`x = tila.zeros(...)` 且 x ∈ 该集合才登记为累加器。由此
  AccumRead 禁令精确覆盖真累加器——普通 zeros tile（从未被 `+=`）在体内
  可读，不误伤。
- **id 命名实现**：种子 = 赋值名（`acc`）；φ = `{name}.loop` / `.loop2`…；
  `+=` 结果 = `{name}.next` / `.next2`…（首个无编号，黄金可读性优先）；
  三者 `src_name` 同为 `acc`（Triton 发射名统一；`.` 不在标识符字符集，
  无冲突）。
- **Triton 侧单元素 zeros shape 带尾逗号**：`tl.zeros((64,), …)`——`(64)`
  在 Python 里不是元组；TIR dump 保持自己的 `(64)` 形态（无尾逗号）。
- **K=0 的契约裁定（评审 §14/§15 后修订）**：shape 含 0 的数组，numpy 的
  strides 全零、torch 对空维报告无意义值（如 `(100,0).stride() == (1,1)`），
  都会误触 RowMajor 连续性契约；裁定 **size-0 数组的布局契约空真**（无元素
  可错读）：interpreter 的 `_is_row_major` 直接放行；launcher 每个 RowMajor
  断言带 `<b>.numel() == 0 or (…)` 守卫（复合式外层括号必须带——顶层以
  `and` 连接而 `or` 结合度更低）。七份 Triton 黄金按此再生成（TIR dump
  逐字节不变）。K=0 的 matmul 差分由此回填（CPU + GPU），充当零迭代恒等式
  测试：`Loop(0, seed, F) = seed` 且 `C = A·B = 0`。
- **`kernel.ops` 消费方全部递归化**：checker `_finalize_ids`、tir printer
  的 namer/walk、launch analysis（拍平）、backend validator、Triton printer
  的 by_id/use_count——匿名编号空间跨层唯一。
- **能力门补洞（评审 §8 的实质化）**：累加路径补上标准 `'+'` 能力检查
  （`_capability_arith`）——fp8 种子的累加器现在 E16 拒绝（storage-only，
  与既有算术纪律一致）。此前累加路径绕过能力门，是实现期真漏洞。

## 13. 评审意见处置（2026-08-24，v0.4 review）

外部评审总评 9/10：核心方向背书——受限累加器优于放开 Python `for`/SSA φ、
`tila.range` 与 `tila.arange` 二分（iteration domain vs tile 构造）、runtime
end + constexpr step 的 compile-once/run-dynamic-K、K 非倍数的 ceildiv 掩码
语义、严格同形累加拒绝隐式广播、zeros 静态 shape、"不引入一般 CFG、select
优先于 if"。逐条处置：

**采纳（本轮落地）**：

- **`+=` 是 primitive accumulator update（必改①；§20 合并）**：表面语义
  直接定义为 `acc⁺ = acc_current ⊕ t`（reduction update），不是
  `acc = acc + t` 的缩写、不是 read-modify-write——编译器隐式以累加器当前
  状态作 update 的 LHS state，该内部状态读不属于表面层累加器读。与
  AccumRead 禁令的表面矛盾由此消解（§1.3 重写；E20 AccumRead 消息改为
  "may not be used as an ordinary expression value…"）。
- **维符号双重视图正式化（必改②）**：DimSymbol（type-level）↔ 运行期物化
  `Scalar(i32)`（value-level）写进 `language-spec.md` §7——`K` 既进注解、
  又作 `tila.range(0, K, BK)` 的 end / `offs < K` 的右部，依据是同一条
  elaboration 规则。实现早已如此（TSymRef），规范补齐。
- **归纳变量不算用户 loop-carried state（必改④）**：不变量改为"除编译器
  生成的归纳变量外，唯一允许的用户可见 loop-carried state 是显式播种的
  累加器"（§0/§2.2/semantic-model §2 同步）——split-K / reduction / 嵌套
  循环下该陈述继续成立。
- **ZeroSeed 降为 distinguished 种子态（强烈建议③，按评审自己给出的折中
  形态采纳）**：规范层不再把 Zeros 当普通 DistLayout term——它记录"分布
  未定"，按定义排除在 equiv 之外、以 join 单位元身份参与合并（L7 = 种子
  物化规则）；累加器检查以状态机表述（Seed → Materialized(L) → same L，
  §2.1/§2.3；checker 的 carried 链即其实现）。
- **零迭代恒等式入 semantic model（§14/§15）**：Loop Semantics 四条方程
  进 `semantic-model.md` §5.5；size-0 数组的 RowMajor 契约裁定空真，
  K=0 matmul 差分回填（CPU + GPU）——identity test：`C = A·B = 0`。
- **累加能力门（§8 的实质化）**：fp8 累加器采纳拒绝——走既有 dtype 能力
  表（E16 storage-only），不另立 AccumulatorDTypes 清单（理由见"部分采纳"）。
  顺带修掉实现漏洞：累加路径此前绕过能力门。
- **start ≡ 0 定性为 syntactic restriction（§6）**：非 semantic
  impossibility——TFor 省略 start 字段即该约束的 IR 投影，将来
  `TFor(start, end, step)` 加回字段即可，不破 IR（§1.1/§9）。
- **φ 类型不变量（§13）**：以精确形态采纳——`type(φ) = type(back)`，pre
  恒为 zeros 种子（join 单位元）故入口值与 φ 类型兼容；评审原式
  `type(pre) = type(φ) = type(back)` 在种子是单位元时恰不成立（那正是
  L7 的用武之地）。非 zeros 种子的将来放开须升级为 equiv 前提
  （ast.md §6 不变量 7；TPhi 已自带 tila_type，printer 无需回查）。
- **loop-carried 语义等价入验收（§16）**：`lower(LoopPhi) = Triton
  loop-carried assignment` 不以黄金字节为准，而以同一 TIR 的
  interpreter/GPU 差分为语义验收（§8.5；测试已有，规范明文）。
- **Loop Semantics 四条方程（§19）**：Range 集 / Acc 递推 / 出口 / 零迭代
  入 `semantic-model.md` §5.5——checker、TIR、interpreter、lowering 全部
  从这四条派生。

**部分采纳**：

- **TPhi → TLoopPhi 改名（§12）**：意图采纳（强调 structured loop-carried φ
  与将来 CFG φ 是两回事），改名不做——当前路线明确不引入一般 CFG（§9），
  φ 在 TIR 中无歧义；docstring 与 §3 显式记名 "structured loop-carried φ"。
- **AccumulatorDTypes 白名单（§8）**：fp8 排除采纳，但不另立清单——Tila
  的能力纪律是"capability 表是唯一权威"（arithmetic.py / E16）；i8 累加
  不比 i8 算术（语言已刻意允许）更危险，按构造另设 dtype 白名单会开第二套
  能力体系的先例。

**拒绝**：

- **把 Zeros 从 `TileType.layout` 整体移出、以独立 AccumulatorState 结构
  承载（§2/§11 的强形式）**：zeros 值不只在累加器路径存在——
  `z = tila.zeros(...)` 是合法 Tile（可 store、可 Zeros⊕Zeros），其类型必须
  携带种子标记，term 的载体没有第二个住处。需要改的是它的**地位**
  （distinguished、equiv 排除、join 单位元）而非载体——这正是评审给出的
  折中 ("keep the implementation, define it at spec level")，按此落地。
