## 0. 设计原则与修订记录

本片段把 Tila 的设计原则再收紧一句：

> **Tila 不创造 Triton 没有的"计算操作"；Tila 创造 Triton 没有的"类型关系与静态证明"。**

据此，二维需要的东西分三层归位：

| 东西 | 归属 | Triton 同构物 |
|---|---|---|
| `tila.expand_dim`、普通比较、`&`、size-1 广播 | 语言原语 / 语言语义 | `tl.expand_dims`、`<`、`&`、原生 broadcast |
| `Product(L₁, L₂)`、律 L5、layout 等价判定 | layout 代数——**Tila 的真正增量** | 无：Triton 只查 shape 可广播，不追踪分布等价 |
| `meshgrid` | 至多前端 sugar（desugar 成 `expand_dim` + 广播），不进文法、不进 TIR | 无核心 API（NumPy 式便利函数） |
| `bounds` | **删除** | 无核心 API |

撤销初稿 `meshgrid`/`bounds` 的三条理由：

1. **它们不是 GPU primitive**。Triton 用 `expand_dims` + broadcast + 比较 + `&` 表达完全相同的语义；`meshgrid`/`bounds` 是 NumPy 风格的便利封装。做成核心语言，Tila 就开始"比 Triton 多几个方便函数"，而不是"把 Triton 隐含的类型关系显式化"。
2. **`bounds` 把 index 和 shape 绑死，且硬编码 `<` 方向**。往后每个相近需求（`<=`、`rows + cols < K`、`x > 0`、析取）都会逼出新的 helper 内建——语言随便利膨胀，而不是随语义生长。
3. **初稿让 `TMeshgrid`/`TBounds` 进了 TIR，IR 被表面语法绑架**。修订后 TIR 只新增 `TExpandDim` 一条指令（`&` 在 v0.1 已随评审入列），每条在 Triton 有 1:1 同构物；lowering 回到纯平移，不再有"使用处分解"这种局部翻译逻辑。

连带效果：row-major 的 dim0 stride（`* N`）从 meshgrid 的 lowering 内部回到用户代码——与 Triton 惯用形完全同构。代价与收益见 §6（stride 与谓词的语义正确性归用户；检查器管符号、shape、layout、dtype 的一致性）。

## 1. 核心原则：变量在 shape，不在分布

batch 会变、特征长度会变——但**线程分布不变**。"会变的量"在 Tila 中的去向：

| 会变的量 | 出现层 | 谁消费它 | 编译期可见性 |
|---|---|---|---|
| 符号维 `M`（batch）、`N`（特征） | Buffer 的 shape、mask 谓词、索引算术 | launcher 传值、mask 语义、地址算术 | 只作为**符号名**参与比较 |
| row-major stride（dim0 的 stride = `N`） | 用户索引算术（`rows2 * N`）与 MemoryLayout（隐式契约） | lowering 的地址展开 | 符号表达式，按名比较 |
| tile 大小 `BM`、`BN` | constexpr | **DistLayout 的种子** | 全静态，唯一决定分布 |

关键论断：**DistLayout 的静态 tile 域由 tile shape——即 constexpr tiling 参数（BM、BN）——决定；运行时 shape（M、N）只参与有效元素谓词（mask）与地址计算（stride），不参与分布等价。** 一个 64×128 的 tile，不管 batch 是 1 还是 777，"哪个线程持有哪个元素"都相同——变化的只是哪些坐标越界（mask 的事）和基址偏移（stride 的事）。若分布依赖运行时值，layout 等价在编译期就不可判定；Tila 把可变性全部隔离在 shape / mask / stride 三处，代数层保持封闭。（"静态 tile 域"的说法也为将来的 warp/lane/swizzle 留位：它们同样是静态量，进得了 DistLayout；运行时 shape 永远进不了。）

与 CuTe 的对应：CuTe 的 symbolic layout（shape/stride 可为动态值）属于**内存布局层**。Tila 的两层划分把这个区分制度化——**MemoryLayout 可以符号化，DistLayout 恒静态**。

## 2. 表面语言的增量

四个小增量，无一引入新语法形式（仍是普通调用与普通运算符）：

- **`tila.expand_dim(t, axis)`**：在 `axis` 处插入长度 1 的轴，`Tile[i32, (64,), L] → Tile[i32, (64,1), L]`。对应 `tl.expand_dims`。仍然不引入 `[:, None]` **下标语法**——插入轴必须用具名内建表达：无下标文法、axis 是显式实参（可判型、可报 E04）、名字与 Triton 逐字对齐；axis 按**结果张量**的轴编号，与 `tl.expand_dims` 的定义一致，可放心写 1:1 映射。
- **size-1 广播（语言语义，非内建）**：v0.1 的 R5（及比较、`&`）要求严格 shape 相等；本片段放宽为右对齐逐轴"相等取之、一方为 1 取另一方、否则 E03"。这就是 Triton/NumPy 的标准广播，一步不多给：同轴双方均 >1 且不等 → 仍 E03。v0.1 的"无隐式广播"承诺由此收窄为"无 **非 size-1** 的隐式广播"。
- **`&`（bool 合取）**：`Tile[bool] & Tile[bool] → Tile[bool]`，shape 按上一条广播（v0.1 已含 `& |`，见 R10）。`and`/`or`（短路语义）依旧禁用——块上短路无意义。
- `program_id` 轴集从 v0.1 的 `{0}` 扩至 `{0,1}`：launcher 生成二维 grid，launch_plan 按轴推导（规则与失败条件见 `triton-lowering.md` §7）。
- 本片段同时**解禁 rank-2 注解**（`tila.Tensor[tila.float32, M, N]`；v0.1 中为 E12）——2D 参数现在可被 `expand_dim` + 广播索引。

（初稿否决项 `idx < (M, N)` 依旧否决：语言无元组。）

## 3. 新增规则与 Product 项

### R13 expand_dim（本片段新增；编号接续 v0.1 的 R12）

```
Γ ⊢ t : Tile[dt, Σ, L]    axis ∈ {0, …, rank(Σ)}
────────────────────────────────────────────────────────────
Γ ⊢ tila.expand_dim(t, axis) : Tile[dt, insert(Σ, 1, axis), L]
```

layout 不变：**长度 1 的轴，其元素分布是唯一的平凡映射——layout 代数对 size-1 轴不可见**。axis 越界或非整型字面量 → E04。
⇝ `tl.expand_dims(⟨t⟩, axis)`（1:1；TIR 新指令 `TExpandDim`）

### R14 size-1 广播（放宽 R5/R6/R10 的 shape 前提）

```
Γ ⊢ t₁ : T[dt, Σ₁, L₁]    Γ ⊢ t₂ : T[dt, Σ₂, L₂]    Σ₁ ⊗ Σ₂ 良式
────────────────────────────────────────────────────────────────────────
Γ ⊢ t₁ ⊕ t₂ : T[dt, Σ₁ ⊗ Σ₂, …]
```

`Σ₁ ⊗ Σ₂`：右对齐逐轴 `(a, b) ↦ a（a=b）/ b（a=1）/ a（b=1）/ ✗ E03`。

layout 推导（本片段的核心新增）：**逐轴取非平凡侧的分布**。秩 r 的结果，其 layout 是 r 个轴分布的 `Product`；某轴上只有一方非平凡（长度 >1）→ 取该方分布；两方都非平凡 → 回到 v0.1 规则要求 `L₁ ~ L₂`（不等价 → E05），取其一；一方是标量 → R4 原样（`BcastScalarL` 被律 L2 擦除，标量广播不引入任何项）。

**广播在 TIR 中不设指令**：`TArith`/`TCmp`/`TLogic` 的操作数 shape 从"严格同形"放宽为"⊗ 良式"，发射时由 Triton 原生 broadcast 完成——与 Triton 同构，translator 不多做一个动作。

### R15 `&` 合取（v0.1 R10 的广播化）

```
Γ ⊢ m₁ : Tile[bool, Σ₁, L₁]    Γ ⊢ m₂ : Tile[bool, Σ₂, L₂]    Σ₁ ⊗ Σ₂ 良式
────────────────────────────────────────────────────────────────────────────
Γ ⊢ m₁ & m₂ : Tile[bool, Σ₁ ⊗ Σ₂, …]（layout 推导同 R14）
```

### Product 项与律 L5

```
L ::= … | Product(L₁, L₂)
(L5)  norm(Product(a, b)) = Product(norm(a), norm(b))     # 同余律
```

语义：`Product(L₀, L₁)` 不是"二维 layout"，而是**独立坐标映射的笛卡尔复合**——`L₀ : lane → row`、`L₁ : lane → col`，则 `Product(L₀, L₁) : lane → (row, col)`。这里的 lane 是抽象槽位（分布族标记）；`Product` 是 **Tila 语义分布积**——声明两轴分布独立、可作为一等 term 参与等价判定，**不声称** GPU 上的实际 distributed layout 等于这个外积（与 Triton concrete encoding 的对接是桥接问题，`type-system.md` §3.2/§5，本片段不预设结论）。它复合的是两个一维分布，不绑定"2"这个秩：`Product(Product(L₀, L₁), L₂)` 即三维分布。本片段不为 3D 开文法（§7），但代数定义从现在起就按可复合写。单位元（size-1 轴）：`Product(L, Identity(())) = L`。

normal form 保持 `Product(identity(64), identity(128))` 的可见结构（不塌缩成匿名 Identity），让诊断能说清"行来自 L0、列来自 L1"。v0.1 的观察"正规形式恒为 Identity"从此打破——**这个片段起，正规形式真正分支，L5 与既有 L1–L4 产生非平凡交互**（见 §4 判定日志）。

## 4. batched_add 完整走查

源码见 `examples/batched_add.tila`（kernel 部分）：

```python
import tila


@tila.jit
def batched_add(
    a: tila.Tensor[tila.float32, M, N],
    b: tila.Tensor[tila.float32, M, N],
    c: tila.Tensor[tila.float32, M, N],
    BM: tila.constexpr = 64,
    BN: tila.constexpr = 128,
):
    pid_m = tila.program_id(0)
    pid_n = tila.program_id(1)
    rows = pid_m * BM + tila.arange(0, BM)
    cols = pid_n * BN + tila.arange(0, BN)
    rows2 = tila.expand_dim(rows, 1)
    cols2 = tila.expand_dim(cols, 0)
    idx = rows2 * N + cols2
    mask = (rows2 < M) & (cols2 < N)
    x = tila.load(a + idx, mask=mask)
    y = tila.load(b + idx, mask=mask)
    z = x + y
    tila.store(c + idx, z, mask=mask)
```

命名说明：`expand_dim` 的结果一律用新名（`rows2`/`cols2`）——Tila 单赋值，E14 禁止重绑定。

```
Γ:  a, b, c : Buffer[f32, (M, N)]    M, N : Scalar(i32)（符号维自动绑定）
    BM = 64, BN = 128（constexpr）
```

| 源码 | 规则 | 推导出的类型 | 规范化 layout |
|---|---|---|---|
| `pid_m = tila.program_id(0)` | R1 | `Scalar(i32)` | — |
| `pid_n = tila.program_id(1)` | R1 | `Scalar(i32)` | — |
| `rows = pid_m * BM + tila.arange(0, BM)` | R3+R4 | `Tile[i32, (64,), …]` | `L0 = identity(64)` |
| `cols = pid_n * BN + tila.arange(0, BN)` | R3+R4 | `Tile[i32, (128,), …]` | `L1 = identity(128)` |
| `rows2 = tila.expand_dim(rows, 1)` | **R13** | `Tile[i32, (64,1), L0]` | `L0`（size-1 轴分布平凡） |
| `cols2 = tila.expand_dim(cols, 0)` | **R13** | `Tile[i32, (1,128), L1]` | `L1` |
| `idx = rows2 * N + cols2` | R4+**R14** | `Tile[i32, (64,128), Product(L0,L1)]` | `L2 = product(L0,L1)` |
| `mask = (rows2 < M) & (cols2 < N)` | R6+**R15** | `Tile[bool, (64,128), L2]` | `L2` |
| `x = tila.load(a + idx, mask=mask)` | R7+R8+L1 | `Tile[f32, (64,128), L2]` | `L2` |
| `y = tila.load(b + idx, mask=mask)` | R7+R8+L1 | `Tile[f32, (64,128), L2]` | `L2` |
| `z = x + y` | R5 | `Tile[f32, (64,128), L2]` | `L2` |
| `tila.store(c + idx, z, mask=mask)` | R9：rank 2=2 ✓ shape ✓ dtype ✓ `L2~L2~L2` ✓ | `()` | — |

两处关键分解：

- `idx = rows2 * N + cols2`：`rows2 * N`（R4，标量在右）→ `(64,1)`、L0 不变；`+ cols2`（R14）→ `(64,1) ⊗ (1,128) = (64,128)`，axis0 取 L0、axis1 取 L1 → `Product(L0, L1)`。
- `mask = (rows2 < M) & (cols2 < N)`：两个 R6 比较得 `Tile[bool,(64,1),L0]`、`Tile[bool,(1,128),L1]`；`&`（R15，广播同 R14）→ `(64,128)`、`Product(L0,L1)`——与 load 产出的 tile 同 layout，R8 的 `L_m ~ L` 前提成立。

`z = x + y` 的判定日志（注意 M、N 全程只出现在类型里的 shape 和 MemoryLayout 的记号中，layout 判定与它们无关）：

```
line 33  z = x + y
    dtype : f32 == f32                              ok
    shape : (64,128) ⊗ (64,128) = (64,128)          ok
    layout: load(M_rm(M,N), product(L0,L1)) ~ load(M_rm(M,N), product(L0,L1))
            normalize ⇒ product(identity(64), identity(128)) == product(identity(64), identity(128))
                                                                     ok   （L1 ×2 + L5）
```

## 5. lowering 映射（片段）

初稿的"使用处分解"（`TMeshgrid`/`TBounds` 在 load/store 处展开）整个消失，映射回到逐条平移：

| TIR 指令 | Triton 展开 |
|---|---|
| `TExpandDim(t, a)` | `tl.expand_dims(⟨t⟩, a)` |
| 其余（`mul`/`add`/`lt`/`and`/`load`/`store`/…） | 同形表达式（v0.1 映射表不变）；size-1 广播由 Triton 原生 broadcast 完成 |

生成代码（`examples/batched_add.lowered.py`）与 Tila 源码**逐行同构**——这正是"与 Triton 同层级的 frontend"的验收标准。Tila 的增量不在生成的代码里，在类型推导里：Triton 只知道 `(64,1)` 与 `(1,128)` 可以广播；Tila 还静态知道并判等了两条分布——

```
rows                : Tile[i32, (64,),    L0]
expand_dim(rows, 1) : Tile[i32, (64,1),   L0]
cols                : Tile[i32, (128,),   L1]
expand_dim(cols, 0) : Tile[i32, (1,128),  L1]
idx / mask          : (64,128)            Product(L0, L1)
```

    M, N = a.shape

## 6. 符号维的检查细节

- shape 比较按符号名：`(M, N) ≡ (M, N)` ✓；`(M, N) ≢ (M, K)`——即便 launcher 运行时 N==K，编译期也判不同符号（宁可保守）。
- **初稿的 `bounds` 实参顺序盲区随 `bounds` 一起消失**：维与界的对应现在由用户逐维写明（`rows2 < M`、`cols2 < N`），不再存在"内建参数顺序"这个出错面。
- **残余盲区（翻译语义的固有代价，明说）**：谓词与 stride 的**语义正确性**编译器不证——`rows2 * M + cols2` 或 `rows2 < N` 同样类型合法（符号存在即过 E07，shape/layout/dtype 一致即过），但产出错误结果。`idx` 里的 `N` 是否真是 a 的 dim1，属于用户责任，与 Triton 相同。维度绑定索引（索引 tile 记录其来源维）仍是 v0.3 候选。
- 多个张量注解共享符号（a/b/c 都用 M、N）是运行时契约，由 launcher 的 assert 执行（§5）。
- `rows + cols`：严格同形下 `(64,) ⊕ (128,)` → E03；本片段后若 BM = BN 则合法（同形、L0 与 L1 此时同正规形式）。Tile 不携带"我索引哪个维度"的语义——维度语义由用户经 `expand_dim` 的 axis 与谓词显式建立，想强区分就用不同的 BM/BN。

**E05 何时才真正独立出现**：本片段中 `Product` 的形状与 layout 同构（行、列交换必然形状不同，先被 E03 挡住）。真正"shape 相同而 layout 不同"的错误要等 `transpose(L)`/`reshape(L)` 项进入（v0.2 主线）——这也是检查顺序定为 dtype → shape → layout 的深层原因之一：大量 layout 错误天然被 shape 检查前置拦截。

## 7. 片段边界（不做）

循环与累加、显式 stride 注解（`tila.Tensor[tila.float32, M, N, strides=(s,1)]`）与非连续张量、`transpose/reshape` 的 layout 律、`convert` 显式布局转换、`dot`/MMA、大于 2 维（`Product` 的复合已按 3D 预留，文法不开）、`\|`/`~`（布尔代数只开 `&`）、`where/select`、`meshgrid` 式前端 sugar（可有可无，永远不进 TIR）。符号维依旧不进入 DistLayout——这条边界是永久设计，不是阶段限制。
