# ADR-020：类型、数值与 Safe 结论的正确性收口

- 状态：Accepted
- 日期：2026-09-20
- 范围：修复已复现的错误 Safe、入口精化、静态分支合并与指针累计位移；暂停 M4-05d 及功能扩展。
- 补充 ADR-007、ADR-011、ADR-013；验收记录见 [正确性审计](../correctness-closure.md)。

## 统一前提

Safe 表示在所记录的事实、path、mask 和已履行的启动契约下，访问坐标满足边界。
它不表示任意宿主绑定都合法，也不证明一般无竞争、所有权、同步正确或结果确定性。
合法启动还必须通过类型/capability、ABI/refinement、数值定义域、地址及 target 门禁。
unsafe 只豁免对应 bounds 义务；不豁免这些执行前提。warn 模式不等于完整证明。

数学表达式仅在定义域内允许保真规范化。相同规范键必须蕴含相同值；不能因显示
方便丢掉负号。规范键相异可以漏掉等价式，不能反过来猜相等。消去后的表达式
不能替代原始运算的定义域和中间溢出检查；规范化、事实生成与快速证明均属于可信基。

## 入口浮点值

宿主整数精确值或 binary64 浮点值先按声明的 f16/bf16/f32/f64 作 RNE 舍入，
再检查全部 refinements。同一个舍入结果用于分析和 CPU/GPU 实参，不能检查原值
后交给后端自行窄化。精确整数不得先转 binary64 再转较窄格式，避免双重舍入。

有限源转换溢出报 TILA-NUM-002；下溢允许产生有符号零，但必须满足转换后的
refinement。已有 NaN/Infinity 输入仍按 IEEE 值处理，各 refinement 自行判定；
这不新增 Finite 契约。浮点普通算术/归约的舍入与非正规数行为仍遵循已有后端契约。

## 静态分支

采用保守合并，不引入条件类型或新的特化编译器：只有 dtype、rank、逐维 shape
等价的值可以在合并后使用；不同的 Const 形状也成为 static-variant，使用时报
TILA-TYPE-020。嵌套分支的 variant 必须沿任一活跃前驱传播，不能被外层合并抹除。
提前 return 的非活跃前驱不参与合并。分支内部的不同形状仍合法。

这是有意的兼容性收紧：原先跨分支共享长度 4/8 的索引和值，即便某些特化恰好
可执行，也须将消费操作移入各自分支或对齐形状。两分支仍分别检查并保留在 TIR；
原有 deferred Const 等式仍在 materialize/launch 复核。本次不承诺仅检查所选分支。
未来若恢复跨分支不同形状，必须另行设计条件类型或特化后完整重检及分析重建。

## 指针地址域

指针根对应其传入 view 的起点，累计偏移以元素为单位；普通整数表达式先按其
声明位宽求值，再进入地址域。每步偏移与从根累计偏移乘以元素字节数，均必须
可表示为 signed i64。不能证明时在启动前报 TILA-NUM-001，不能允许回绕后抵消。

CPU 用数学加法检查范围再存入 i64；Triton 对每步元素偏移显式转换为 i64。
数值门禁跟踪 Ptr 参数、buf.ptr、定义、分支和循环；未知循环携带指针不能被猜成
零偏移。不访问内存的临时指针可以在 extent 外，真正访问仍须另过 bounds；
此规则不保证传入宿主对象本身的底层分配有效性，不建立所有权。

## Safe 规则与证据

所有成功规则都须证明 `F ∧ path ∧ mask ⇒ 0 ≤ coordinate < extent`，或证明
访问不可达；F 必须携带正确作用域、值身份与来源。规则清单、分别使用的前提与
反例测试由正确性审计维护。快速规则不强制重复调用 SMT，但新增/更改规则必须
有独立蕴含查询或小域枚举对照；SMT 编码仍须单独与实际执行比对。

机器值精确 BitVec 编码允许回绕；将它视为普通数学整数运算才需要无溢出依据。
除零等定义域不能作为额外假设排除反例。矛盾 UserAssumption 不得产生无条件 Safe；
未验证 grid 契约保持 pending/Unknown；求解超时、资源耗尽不产生 Safe。
缓存复用同样受这些责任约束，且启动契约每次重验。本次提升编译语义版本与证明
编码版本，隔离修复前的缓存含义。

## 验收与限制

C1 复核补充：按 ADR-012 拒绝 Mask cast，合法 Block cast 必须保形；WriteOnly
不能读取，包括 unsafe/false mask，frontend 与 verifier 分别检查。Const 分支
return 的 lowering 将后续操作保留在活跃分支；runtime if/循环内 return 在固定
GPU target 尚不支持，提前 TARGET-009 拒绝，CPU 保留原语义。证据见
[C1 复核](../c1-correctness-review.md)。这不是新增 Mask API 或完整 GPU 退出转换。

固定反例、规范化小域性质、逐条 Safe 蕴含、缓存/来源隔离、CPU 全量与固定 RTX 3090
严格审计共同验收。旧 golden 的成功不是语义正确性的替代证据；不得仅刷新快照
消除失败。本次不宣称已形式化验证整个编译器，也不增加 atomic/race/uniformity
支持范围；M3 的隔离 GPU CI 缺口继续存在。
