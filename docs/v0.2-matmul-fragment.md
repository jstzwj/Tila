# matmul fragment：`tila.dot` 与 MMA 布局（v0.2 片段二）

状态：设计定稿（2026-08-24）。本文定义单发 `dot`（无 K 循环）的表面语言、
类型规则 R16、新的非擦除 layout term `Mma`、R9 的内存边界修订（R9'）、
诊断码 E18，以及桥接问题（`type-system.md` §5 / `development-plan.md` §11-1）
的第一个可证伪假说与 oracle 实验。K 循环与累加（打破单赋值）、tf32/fp8
操作数、`convert(L → L')` 代价模型均不在本片段。

---

## 0. 问题：第一个"外来"布局

v0.1–v0.2 预览中，一切 layout 都从 `arange` 种子推导（identity / product），
等价判定 = 种子结构相等。`tl.dot` 打破这一点：MMA 指令要求操作数与结果
驻留在**硬件规定的 MMA 布局**里，Triton 会为 dot 的结果分配
`#ttg.mma_layout`（oracle 实测见 §5）——它与输入的分布**无推导关系**。
Tila 的 layout 代数第一次需要一个不由种子产生的 term。这正是设计文档所说
"桥接问题的第一个实例"：Tila 等价类如何容纳一个由**后端**决定、而非由
**来源**决定的分布？

## 1. 表面语言

```python
import tila


@tila.jit
def matmul(
    a: tila.Tensor[tila.float16, M, K],
    b: tila.Tensor[tila.float16, K, N],
    c: tila.Tensor[tila.float32, M, N],
    BM: tila.constexpr = 64,
    BN: tila.constexpr = 128,
    BK: tila.constexpr = 64,
):
    pid_m = tila.program_id(0)
    pid_n = tila.program_id(1)
    rm = pid_m * BM + tila.arange(0, BM)
    rn = pid_n * BN + tila.arange(0, BN)
    rk = tila.arange(0, BK)
    rm2 = tila.expand_dim(rm, 1)              # (BM,1)
    rk2 = tila.expand_dim(rk, 0)              # (1,BK)
    rk3 = tila.expand_dim(rk, 1)              # (BK,1)
    rn2 = tila.expand_dim(rn, 0)              # (1,BN)
    a_idx = rm2 * K + rk2                     # (BM,BK)
    b_idx = rk3 * N + rn2                     # (BK,BN)
    c_idx = rm2 * N + rn2                     # (BM,BN)
    a_m = (rm2 < M) & (rk2 < K)
    b_m = (rk3 < K) & (rn2 < N)
    c_m = (rm2 < M) & (rn2 < N)
    x = tila.load(a + a_idx, mask=a_m, other=0.0)
    y = tila.load(b + b_idx, mask=b_m, other=0.0)
    acc = tila.dot(x, y)                      # Tile[f32, (BM,BN), Mma(BM,BN,BK)]
    tila.store(c + c_idx, acc, mask=c_m)
```

**正确性包络（明说，翻译语义的固有代价）**：单发 dot 只覆盖一个 K 块。
masked load 以 `other=0.0` 补齐，故 `K ≤ BK`（含 K 非 2 的幂、非整除）结果
正确；`K > BK` 时只算了部分和——完整 K 归约需要 K 循环（v0.2 主线，本片段
不含）。此包络与 stride 一样属于用户责任；维度绑定索引（v0.3 候选）将来
可将其转为编译期检查。

## 2. 类型规则 R16（dot）

```
Γ ⊢ x : Tile[dt, (M, K), Lx]    Γ ⊢ y : Tile[dt, (K, N), Ly]     （dt 相同）
dt ∈ {f16, bf16}                M, N, K 静态且 ≥ 16
────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.dot(x, y) : Tile[f32, (M, N), Mma(M, N, K)]
```

- **操作数布局无前提**：dot 按坐标语义消费任意布局（Lx、Ly 不受限制）——
  它本身就是一个"布局家族的边界"：blocked 进，MMA 出。
- **结果布局是新的种子类 term**：`Mma(m, n, k)` 不从任何 arange 推导，
  结构相等即等价（`Mma(64,128,64) ≡ Mma(64,128,64)`，≢ identity/product）。
- 结果 dtype 恒 f32（MMA 累加精度；tf32/fp8 操作数是后续片段）。
- 一切前提不满足 → **E18 DotConstraints**（新诊断码；dtype 混用、extent
  < 16、rank ≠ 2、收缩维不匹配统一归此码，消息给出期望形态）。

## 3. layout 代数增量

```
L ::= … | Mma(m: int, n: int, k: int)
```

- `normalize(Mma) = Mma`（正规形式，与 identity 同为种子类）。
- `equiv` = 结构相等：**Mma 与 identity/product 族互不等价**。
- JoinL/CastL 等擦除律不变——但 R5/R6/R10 的等价前提使得**家族混算在
  寄存器内被拒绝**（`acc + blocked_tile` → E05，hint 说明混族需经内存边界
  或显式 convert（未来））。这是刻意收紧：混族运算在 Triton 中合法但会
  触发隐藏的 convert_layout（真实代价）；Tila 把它变成显式决策。

### R9'（内存边界修订）：store 不再检查 layout 等价

v0.1 的 R9 要求 `L_v ~ L_p`；本片段修订为 **store 只检查 dtype 与 shape**。

理由（把 L1 的洞见对称化）：`store(ptr, v)` 的语义是**逐坐标**写
`v[i,j] → ptr[i,j]`——分布描述"谁持有哪个元素"，只影响搬运代价，不影响
坐标语义；load 侧的 L1（结果取索引布局）早已隐含同一立场。MMA 结果直接
写回 blocked 索引的地址因此合法（Triton 在此处做的正是这个语义）。
E05 仍然可达（寄存器内家族混算），且 transpose/reshape 进入后真正独立出现。

**布局不变量（修订后）**：一次 kernel 内，寄存器驻留的每条数据流的布局
族单一；家族切换只发生在（a）dot 边界（blocked → MMA，构造性的），
（b）内存边界（免费，坐标语义）。无隐藏转换、无转换风暴。

## 4. TIR / lowering / interpreter

| 层 | 增量 |
|---|---|
| TIR | `TDot(a, b)`，opcode `dot`；结果类型携带 `Mma(m,n,k)` |
| dump | `%acc = dot %x %y : Tile<f32, (64,128), L3>`，定义行 `L3 = mma(64,128,64)`（统一 L 命名序） |
| lowering | `tl.dot(<x>, <y>)`（默认 f32 累加，1:1 平移） |
| interpreter | `x.astype(f32) @ y.astype(f32)`（fp16 乘积在 f32 中精确；求和顺序差异由差分容差覆盖） |

## 5. 桥接假说（可证伪）与 oracle 实验

**假说 H1**：在单次编译内，"Tila 布局族单一 ⇒ Triton concrete encoding
单一"对包含 dot 的 kernel 成立，且 dot 结果的 encoding 自成一类（MMA 家族），
其上下游值按 §3 的边界规则各归其族。

**实验结果（2026-08-24，TITAN Xp / triton 3.7.1，详见
`docs/layout-oracle-notes.md` 的 MMA 观测节）**：

- ✅ **家族级分离成立**：dot 结果驻留独立 encoding（本机无 Tensor Core，
  以 FMA 下探为独立的 blocked 参数；Tensor Core 机器上预期 mma_layout，
  待复测）；`Mma ≢ Product` 在 concrete 层同样成立；R9' 坐标语义被接受。
- ❌ **强形式证伪**：b 链与 c 链在 Tila 中同为 `product(L0,L1)`，Triton 却
  分配了不同的 blocked 参数（tpw=[2,16] vs [1,32]）——Triton 按数据流择参，
  不按等价类。"Tila 等价 ⇒ 相同 encoding" 不可作为规范承诺；其正确角色是
  "无隐藏转换"的启发式检查。本 kernel 唯一的 convert_layout 来自 dot 操作数
  入场（MMA 固有代价，swizzled shared staging），与 §3 的边界建模一致。

**教训顺带记录**：本片段实现期间，示例初版把 B 的行主序偏移写成
`rk * K + n`（正确为 `rk * N + n`）——类型合法、结果错误、编译器无法拦截，
由 interpreter 差分当场抓获。这是"手工线性化盲区"的活例，直接强化了
stride 化 MemoryLayout（符号化寻址）的优先级。

## 6. 边界（不做）

K 循环与累加变量（打破单赋值，需要 φ 或显式可变绑定——v0.2 主线的
最大语义变更）、`acc` 实参 / `out_dtype`、tf32 / fp8 / int8 操作数
（fp8 需要 B01 架构门）、`convert(L → L')` 与代价模型、多 dot 的布局
择优（两个不同 (m,n,k) 的 Mma 值混算 → E05，hint 指向内存边界）。

## 7. 验收

- `examples/matmul.tila` 全链路：TIR dump 黄金、GPU 与 `torch.matmul`
  差分一致（M,N 含非整除情形；K ≤ BK 含非 2 的幂）。
- E18 矩阵（dtype/extent/rank/收缩维）+ 家族混算 E05 + R9' 放宽的正例
  （MMA 结果直接 store）。
- interpreter 与 GPU 双路径一致（同一 TIR）。
- H1 实验数据落入 oracle 笔记。
