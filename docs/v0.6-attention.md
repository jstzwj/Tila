## 0. 动机：第三个 kernel 形态——两个分布家族必须相遇

### 0.1 问题

v0.4 交付了"乘加"（matmul：dot 的 K 循环累加），v0.5 交付了"激活归一化"
（softmax：逐元素 + 轴归约，**Product 族内闭环**）。attention 是二者的合成：

```
attention 行算法：  QK = q·kᵀ → softmax(QK) 行归一化 → ·V
```

它与前两个形态有一个**本质差异**：softmax 作用在 `dot` 的结果上——归约第一次
必须跨过 Mma 家族边界。这恰好是 v0.5 留下的两个"正题"缺口：

1. **marginal 分支五**（v0.5-reduce §2.1）：Mma 输入的归约 → E21
   ReduceLayout（"语义层边缘化未定义"）——attention 的 `max/sum(QKᵢ,·)`
   直接命中；
2. **非 zeros 种子**（v0.4 §9 既定推迟项）：online softmax 的 running max
   需要 `full((BM,), −∞, f32)` 种子——N > BN 的 attention 必需。

以及一个 v0.5 期间未显形的新问题：**掩码与 Mma 值的相遇**。softmax 的列掩码
惯用法 `where(m_qk, qk, −∞)` 中 cond 来自坐标比较（Product 族）、值来自 dot
（Mma 族）——v0.5 的 R22 三方归并会以 E05 拒绝。没有这条掩码，补零列会污染
max 与分母（softmax 的平移不变性救不了分母，§1.5 拒绝表），**attention 不可写**。

### 0.2 两个里程碑，两个 calculus（评审 §1/§24 采纳）

**v0.6a 是 layout-system 里程碑**——四条新增语义，全部在分布代数内：

```
1. marginal(Mma) → Slice        分布代数扩展（边缘化覆盖原子家族）
2. Predicate Transparency       where 的谓词不进布局代数
3. One-sided Read Join          广播侧免检（仅限唯一全形持有者在场；
                                 v0.6a 前称 R-BT）
4. Slice provenance             Slice ≢ Identity，不强迫等价
```

**v0.6b 是 loop-state-system 里程碑**（Stateful Loop Extension）——φ、
state、read-after-phi、多更新算子、state handoff：它修改 E14/E20/φ 语义/
assignment 语义/读语义/种子语义，**一次改七个面，故以 prototype 立项、独立
验收后再进主规范**（评审 §25）。

### 0.3 v0.6 的真正主题：ownership 与 read 的分离（评审终评采纳）

```
                 Tila Type
        ┌───────────────────────┐
        │      Value Type       │
        │ dtype × shape × dist │
        └──────────┬────────────┘
          ┌────────┴────────┐
       Memory            Distribution
       semantics            semantics
       strides          Product/Mma/Slice
                             │
                        loop state / φ
```

v0.6 真正发生的不是"加入 attention API"，而是：**Tila 开始需要区分"谁拥有
结果元素"（ownership）与"谁只是被读取"（read）**。Owner/Reader 纪律
（§2.2 的 R-BT/R-PT/R-ST/R-φT 四规则；评审 D 统一命名为 strict_join /
read_join，见 `type-system.md` §3.5）是这个区分的形式化——把它定义得足够严，v0.7 的 LayerNorm/RMSNorm/GELU/RoPE
会越来越自然；放得太宽，v0.7 之后就会退化成"layout 不匹配就说它只是被
读取，所以放行"。这正是 oracle 第三轮先行、v0.6a 当作一次 layout-calculus
实验来打的理由。

**不变量（两个里程碑共用一句话；术语句 2026-08-24 评审定案——"家族"改为
"派生闭包"，见 `type-system.md` §3.2 的三类 DistExpr 角色）**：

> softmax 的 tile distribution 在 **Mma primitive distribution 的派生闭包内
> 传播**（Mma → Slice → expand → read_join 逐元素 → Mma——Base `Mma` /
> Derived `Slice` / Composite `Lift`（v0.6a 更名自 Broadcast）三类 DistExpr
> 角色的配合）；**家族切换仍
> 只发生在 dot 边界（构造性）与内存边界（坐标语义）**；被读取的操作数不把
> 自身分布强加给结果的持有方。

## 1. 表面语法

### 1.1 v0.6a 目标程序：attention fragment（验收载体）

```python
import tila


@tila.jit
def attention(
    q: tila.Tensor[tila.float16, M, D],
    k: tila.Tensor[tila.float16, N, D],
    v: tila.Tensor[tila.float16, N, D],
    o: tila.Tensor[tila.float16, M, D],
    BM: tila.constexpr = 64,
    BN: tila.constexpr = 64,
    BD: tila.constexpr = 64,
):
    pid = tila.program_id(0)
    rm2 = tila.expand_dim(pid * BM + tila.arange(0, BM), 1)   # (BM, 1)  行坐标
    rn2 = tila.expand_dim(tila.arange(0, BN), 0)              # (1, BN)  N 方向列坐标
    rn3 = tila.expand_dim(tila.arange(0, BN), 1)              # (BN, 1)
    rd2 = tila.expand_dim(tila.arange(0, BD), 0)              # (1, BD)  D 方向列坐标
    rd3 = tila.expand_dim(tila.arange(0, BD), 1)              # (BD, 1)
    m_qk = rn2 < N                                            # (1, BN)  列掩码

    q2 = tila.load(q, (rm2, rd2), mask=(rm2 < M) & (rd2 < D), other=0.0)  # (BM, BD) f16
    k2 = tila.load(k, (rn2, rd3), mask=(rn2 < N) & (rd3 < D), other=0.0)  # (BD, BN) f16 ← 坐标转置
    v2 = tila.load(v, (rn3, rd2), mask=(rn3 < N) & (rd2 < D), other=0.0)  # (BN, BD) f16

    qk = tila.dot(q2, k2)                          # (BM, BN) f32   Mma₁ = Mma(BM,BN,BD)
    qk_ = tila.where(m_qk, qk, tila.neg_inf)       # 掩码列不进 max（R-PT：谓词不进布局代数）
    mx = tila.max(qk_, axis=1)                     # (BM,)          Slice(Mma₁, 1)（分支六）
    mx2 = tila.expand_dim(mx, 1)                   # (BM, 1)
    p = tila.exp(qk_ - mx2)                        # (BM, BN) Mma₁（R-BT；掩码列 e⁻ⁱⁿᶠ=0）
    s = tila.sum(p, axis=1)                        # (BM,)          Slice(Mma₁, 1)
    s2 = tila.expand_dim(s, 1)                     # (BM, 1)
    w = p / s2                                     # (BM, BN) Mma₁（R-BT）
    y = tila.dot(tila.cast(w, tila.float16), v2)   # (BM, BD) f32   Mma₂ = Mma(BM,BD,BN)
    tila.store(o, (rm2, rd2), tila.cast(y, tila.float16), mask=(rm2 < M) & (rd2 < D))
```

要点：

- **k 以坐标转置入场，无 `trans` 内建**：`load(k, (rn2, rd3))` 的坐标元组
  （(1,BN) 行坐标, (BD,1) 列坐标）广播出 **(BD, BN)** tile——kᵀ 的转置视图。
  这是**坐标可表达性原则**（§1.5）的第一个受益者。
- **正确性包络（明说，v0.2 fragment 同款纪律）**：M 任意（grid 轴 0）；
  **N ≤ BN**（softmax 行耦合使 N 不可跨 program 切分——这是 attention 与
  matmul 的本质区别，也是 flash 存在的原因；N > BN 属 v0.6b）；
  **D ≤ BD**（收缩维补零安全：0·0 = 0）；静态维 BM/BN/BD ≥ 16（R16）。
  **block 组合受目标 SM 共享内存约束**（实现期实测：BN=BD=128 的 dot
  组合需 64KB 共享内存，超本机 TITAN Xp 的 48KB 硬件限——与手写 Triton
  同款约束；典型 flash 配置 BD=64 不受限）。
- **数值卫生（semantic-model 合同，§10）**：`qk_ − mx ≤ 0` 恒成立 → exp
  无上溢；每行至少一个有效列（N ≥ 1）→ mx > −∞ → 掩码列 `exp(−∞ − mx) = 0`
  **无需第二个 where**，sum 的补零列天然贡献 0；s ≥ exp(mx − mx) = 1 →
  无除零。全负行、大 logits 由构造安全。
- **非活跃行明示**（评审 §19 采纳）：i ≥ M 的行（q2 补零 → qk = 0 →
  softmax 值无意义）是 **semantically arbitrary——所有 store 被掩码**。
  未来读者不应误以为 M 外的行满足 softmax 恒等式；垃圾有界、出口被掩码
  收割，与 v0.5 softmax 的 dead-lane 卫生同款。
- **dtype 纪律**：f16 进出、f32 内部（dot 恒 f32 出、exp f32 原生）；第二
  个 dot 前显式 `cast(w, f16)`（R16 操作数门）。单项 f16×f16 乘积可在 f32
  中精确表示；端到端与 torch f32 参考的差异由累加/归约顺序与超越函数实现
  主导（差分容差覆盖，评审 §20 措辞）。

### 1.2 v0.6b 目标程序：online softmax（Stateful Loop Extension 的验收轨迹）

```python
    q2 = tila.load(q, (rm2, rd2), mask=(rm2 < M) & (rd2 < D), other=0.0)   # 循环外一次载入

    m = tila.full((BM,), tila.neg_inf, tila.float32)    # running max 种子（max 零元）
    l = tila.zeros((BM,), tila.float32)                 # running sum 种子（sum 零元）
    acc = tila.zeros((BM, BD), tila.float32)            # 输出累加种子
    for n0 in tila.range(0, N, BN):
        rkn = rn2 + n0                                 # (1, BN) 当前列块坐标（n0 是偏移）
        rvn = rn3 + n0                                 # (BN, 1)
        k2 = tila.load(k, (rkn, rd3), mask=(rkn < N) & (rd3 < D), other=0.0)
        v2 = tila.load(v, (rvn, rd2), mask=(rvn < N) & (rd2 < D), other=0.0)
        qk = tila.dot(q2, k2)                          # (BM, BN) Mma₁
        qk_ = tila.where(rkn < N, qk, tila.neg_inf)    # R-PT
        rowmax = tila.max(qk_, axis=1)                 # Slice(Mma₁, 1)
        m1 = tila.maximum(m, rowmax)                   # StateRead（入口值，§2.6）→ Slice
        alpha = tila.exp(m - m1)                       # StateRead；首迭代 e^{−∞−m1} = 0 ✓
        p = tila.exp(qk_ - tila.expand_dim(m1, 1))     # Mma₁
        l *= alpha                                     # ScaleUpdate（乘数 R-ST）
        l += tila.sum(p, axis=1)                       # ReduceUpdate；Slice(Mma₁, 1)
        acc *= tila.expand_dim(alpha, 1)               # ScaleUpdate（跨 Mma 乘数 R-ST）
        acc += tila.dot(tila.cast(p, tila.float16), v2)  # ReduceUpdate；Mma₂
        m = m1                                         # HandoffUpdate（semantic move）
    y = acc / tila.expand_dim(l, 1)                    # 终归一化（R-BT；循环后读合法）
    tila.store(o, (rm2, rd2), tila.cast(y, tila.float16), mask=(rm2 < M) & (rd2 < D))
```

三个累加器（m/l/acc）、三种更新形态（AccumulatorUpdate，§1.4）、两类
StateRead（`m` 在 maximum 与 exp 中——均在纯值表达式位）。零迭代（N = 0）
出口 m = −∞、l = 0、acc = 0 → y = 0/0 = NaN——**包络 N ≥ 1**（全掩码块
不进入循环：n0 < N 保证每块至少一个有效列）。**只开 N 循环、不开 D 循环**
（评审 §21 确认）：Q 常驻寄存器、K/V 分块正是 FlashAttention 的基本数据流；
同时解决 N/D 两个循环会一次性引入嵌套循环 + 多累加器 + 多归约维，不需要。

### 1.3 新内建（v0.6b 两件；v0.6a 零件）

**`tila.full(shape, value, dt)`**——常量播种：

- 形态与 `zeros` 全同（shape 位置元组、静态量、rank ≤ 2、DTypeRef、dt ≠
  bool），多一个 **value 实参**：数值字面量或特殊值；类别与 dt 匹配
  （浮点 dt 配 FLOAT/neg_inf、整数 dt 配 INT；跨类别 E02）。value 按
  **full 的显式 dtype** 语境定型（R24 语境来源 +1，§2.4）。
- `zeros` 保留为 `full(…, 0, dt)` 的既名缩写（表面与 TIR opcode 均不变；
  布局 term 更名见 §2.4）。
- **SpecialValue 内部族（评审 §17 采纳，概念层）**：`neg_inf` 在语义/前端
  层归入 `SpecialValue` 族——按 dtype 参数化的
  `neg_inf | pos_inf | nan`；表面语言仍只开放 `neg_inf`（pos_inf/nan 是
  min/argmax/layernorm 的未来消费者，先立概念不开放拼写）。

**`tila.maximum(a, b)`**——逐元素二元 max：

- **`max_axis ≠ maximum`（评审 §18 成文）**：`max(x, axis=k)` 是**轴归约**
  （销毁分布轴——边缘化，R20/分支六）；`maximum(a, b)` 是**值选择**
  （保持分布——`where(a < b, b, a)` 的规范化拼写）。二者属于两个代数，
  TIR opcode（`max` / `maximum`）已分立，规范明文。
- running max 的更新原语。dtype 两侧严格相等（E02）；shape `⊗` 广播
  （E03）；能力门 = `max` 归约同款（`'<'` 域：int+float；bool/fp8 → E16）。
  **layout：同形双侧 equiv（E05）/ 广播侧 R-BT**——与二元算术完全同款，
  无专设规则。零元 −∞ 与归约零元表（v0.5 §1.1）一致；`minimum` 未开放
  （表已有 +∞ 行）。
- NaN 语义不另行规定（与 where 的非严格语义同款立场；flash 的构造使 NaN
  不可达——`m1 > −∞` 时 `m − m1` 无 NaN 源，§1.2 注）。

### 1.4 AccumulatorUpdate：更新形态正式化（v0.6b；评审 §11/§12/§26 采纳）

v0.4 立法："⊕ 目前只有 `'+'`；reduction update 家族沿同一形态泛化"。
v0.6b 把更新正式化为 **Tila AST 的一个语句类别**（而非对 Python Assign 的
逐例 patch——普通赋值保持"SSA 定义"的唯一含义，不再承载携带语义）：

```
AccumulatorUpdate
├── ReduceUpdate  ('+=')    acc⁺ = acc ⊕₊ t；shape 严格同形
├── ScaleUpdate   ('*=')    acc⁺ = acc ⊕ₓ t；shape 前提 = ⊗ 广播良式且
│                           结果 shape = acc 的 shape（乘数可广播进累加器，
│                           不放大）——与 '+=' 的严格同形刻意不对称：累加是
│                           聚合语义（隐式广播掩盖错字），重定标是逐行缩放
│                           语义（乘数天然是 (BM,1)，语言内无广播算子可显式
│                           展开）——flash 惯用法倒逼
└── HandoffUpdate ('=')     acc = x：x 必须是**当前迭代内已定义的单一局部名，
                            且非累加器**（E20 HandoffForm）——`m = m1 + 0`、
                           `m = tila.cast(m1, …)`、`m = f(m1)`、`m = m`（自
                            交接 no-op）、`m = l`（跨累加器）都是计算或非法
                            交接而非 state move，一律拒绝。handoff =
                            **semantic move of state**（携带通道直接以 x 为
                            back 边，无额外计算）
```

handoff 存在的理由是 SSA：online max 需要**同时**持有旧值（算 α）与新值
（算 p），`m1 = maximum(m, rowmax)` 是普通表达式（读入口值 m），交接必须
显式。Python 无 `max=` token——函数式表达 + handoff 是 token 集内唯一干净
拼写。

**StateRead 的合法位置（评审 §26 收窄）**：累加器在体内可作为普通表达式
值出现，**读到的 = 当前迭代的入口值（φ）**；更新语句不改变名字在本迭代
表达式中的含义（它们调度的是下一迭代的携带值）。但读**只允许出现在纯值
表达式的操作数位**（算术/比较/where/一元/maximum/归约的操作数）：

```
✓  alpha = tila.exp(m - m1)                # 纯表达式消费
✓  l *= alpha                              # 读派生值喂更新 = 状态系统内部消费
✗  tila.store(o, c, m)                     # 逃逸（store 实参/mask/coords）
✗  x = m; tila.store(o, c, x)              # 经局部名的传递逃逸（单赋值下
                                            # 数据流追溯 = 线性扫描）
```

逃逸位拒绝 → **E20 AccumRead（该 subcode 重新专用于逃逸位）**。这样
v0.6b 没有把"累加器变成任意一等可变变量"的盒子打开——读是状态系统的
内部观察，不是值的出口。定型机制 = **布局元变量 + 出口约束求解**（§2.6）。
围栏其余照旧：复合表达式重写累加器（`l = l * alpha + s`）→ E20——**必须
分解为 primitive updates**；循环局部不出循环。

### 1.5 被拒的替代设计

| 方案 | 拒绝理由 |
|---|---|
| `tila.trans(k)` 转置内建 | **坐标可表达性原则**（评审 §23 升为原则）：当数据访问语义可由既有坐标语义表达时（`load(k, (rn2, rd3))` 即转置视图），不新增原语。`Transpose(L, perm)` 是新布局 term + 与 Product 律的交互设计——为省一次坐标换位不值；真实 kernel 对 coalescing 的追求（load 原向 + trans）留给该 term 的独立设计（§9） |

## 2. 类型层

### 2.1 R20 分支六：marginal(Mma) = Slice(L, k)——边缘化成为全函数

v0.5 的五分支中第五分支（Mma 等"不可按轴分解"的布局）抛 E21。v0.6a 增补
**分支六**，marginal 从此对一切**可达的** rank-2 布局有定义：

```
marginal(L, Σ, k)：
  1–5. （v0.5 既有：Product → 幸存因子 / size-1 轴 → 原样 /
        唯一非平凡轴被归约 → Identity(()) / Seed → Seed(Σ∖k) /
        …）
  6. L 为原子种子类（Mma；非 Product-可分解、双轴或幸存轴非平凡）
      →   Exact(Slice(L, k))
```

（分支四的 `Zeros` 随 §2.4 更名为 `Seed`。）

**新 term**：

```
L ::= … | Slice(L, k)        # rank-1：原子布局 L 沿轴 k 的边缘
                             # ——"幸存轴继承其在 L 的复合分布中的位置"
```

- **语义**：Mma 的行/列分布不是独立轴分布的积（v0.5 拒绝放行的原因），
  幸存轴的边缘分布**没有独立构造的等价物**——它只能以后源（provenance）
  方式陈述：`Slice(Mma₁, 1)` = "这个 (BM,) tile 是 Mma₁ 沿轴 1 的边缘"。
  这正是 H2 实测的 Triton concrete 形态
  （`#ttg.slice<{dim = 1, parent = …}>`）的语义影子——Product 的分支一
  说"边缘 = 幸存因子"（更强的独立声明），Mma 的分支六说"边缘 = 亲代切片"
  （诚实的后源声明）。**角色（评审 A 定案）**：Slice 是 **derived
  provenance expression**（归约产生的派生分布），不是与 Product/Mma 同层
  的分布构造算子——`type-system.md` §3.2 的 DistExpr 三类角色
  （Base/Composite/Derived）与按 term 分表的等价规则。
- **equiv**：`Slice(L₁, k) ~ Slice(L₂, k)` ⟺ `L₁ ≡ L₂`（结构）；
  **`Slice ≢ Identity`**——不强迫等价（评审 §2/§24 背书：比强行发明
  "Mma row layout"干净）。
- **Slice 的能力边界（评审 §3 成文）**：Slice 是**可作为普通 tile 分布被
  读取**的（参与归约、经 expand 被广播读取、作 where/elem 操作数），但
  **不是可与任意同形 tile 做 arithmetic join 的独立分布族**：

  ```
  Slice(Mma₁,1) + Slice(Mma₁,1)   ✓  equiv（同亲代）
  Slice(Mma₁,1) + Identity(BM)    ✗  E05（跨族同形 join，归属真决策）
  ```

- **normalize**：Slice 是正规形式（种子类，同 Identity/Mma）。
- **expand 的还原（L9 的 Mma 对偶，无需新律）**：`expand_dim(Slice(L,k), k)`
  按 R13 **布局项不变**（size-1 轴对布局代数不可见）——`mx2 : (BM,1)` 的
  term 仍是 `Slice(L,k)` 本身；它与 L 的全形 tile 合并时按 R-BT（§2.2）
  直接取全形侧——"边缘化取边缘、升维还原亲代"在 Mma 族内成立，但它是
  **透明规则的推论**而非等式律（与 v0.5 在 Product 内由逐轴因子规则实现
  L9 完全平行：机制不同、效果同构）。跨项（`Slice(Mma₁,k)` 广播位与
  Mma₂ 全形）经 R-BT 同样放行——flash 的 `acc *= expand(alpha,1)` 即此
  形态（乘数只是被逐坐标读取）。
- **E21 ReduceLayout 的命运**：分支六之后，可达布局（Product 族 / Mma /
  Slice / 常量种子）全部有定义——**E21 ReduceLayout 对合法输入成为空位**
  （保留码位防新 term 回归；ReduceRank 仍活跃）。

```
Γ ⊢ x : Tile[dt, Σ, L]    rank(Σ) = 2    dt 具备对应能力（E16）    L 原子种子类
axis ∈ {0, 1}
────────────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.sum(x, axis=k) / tila.max(x, axis=k) : Tile[dt, Σ∖k, Slice(normalize(L), k)>
```

### 2.2 布局相容规则：四条独立规则 + 形式谓词（评审 §4–§8 采纳）

**总原则（口语层）**：凡操作数在运算中只被逐坐标读取（不重排、不搬运
结果元素），其分布不约束结果分布；结果 layout = **持有全部结果元素的一
侧**（全形持有者）的 layout。

**形式谓词（授权门，评审 §6）**——"只被逐坐标读取"的自然语言定义边界太
模糊，新运算申请透明资格必须逐条满足：

```
TransparentRead(op, x) ⟺
  1. x 不决定任何结果元素的归属（ownership 不依赖 x 的布局）
  2. 每个结果元素至多读取 x 的一个对应元素
  3. 不发生 reorder / reduction / scatter
  4. 结果分布由其它操作数（全形持有者）唯一确定
  5. backend 允许按坐标转换读取（convert_layout 有界可实现）

反例（不成立）：transpose（重排）、reduce（销轴）、dot（收缩）、scatter
```

**四条规则（正式类型规则；统称"读透明"仅作口语速记——评审 D 起统一为
Owner/Reader 纪律的实例（read_join 家族），它们不是同一种
读，评审 §4/§5）**：

```
布局相容
├── R-BT  Broadcast Transparency（值广播侧；纯函数读）        [v0.6a]
├── R-PT  Predicate Transparency（谓词侧；select 注记）       [v0.6a]
├── R-ST  State Update Transparency（状态更新读侧）           [v0.6b]
└── R-φT  Phi Read Transparency（携带读，时间语义）           [v0.6b]
```

**R-BT（Broadcast Transparency；R5/R14 修订）**：

```
前提：Σ_b ⊗ Σ_f 良式，且 Σ_f 是唯一全形持有者（one-sided：Σ_b 的
      非平凡轴 ⊆ Σ_f 的非平凡轴，Σ_b ≺ Σ_f）
结论：结果 layout = L_f，广播侧布局免检
边界：同形双侧（Σ₁ ≡ Σ₂）照旧 equiv（E05 主战场不动）；
      双广播侧（(BM,1)⊗(1,BD)→(BM,BN)，无全形持有者）照旧逐轴
      merge_nontrivial——两广播侧无共享非平凡轴，各自提供所在轴的
      分布段，不存在因子等价问题（v0.5 行为原样保留；评审 §7 收窄）
```

**R-PT（Predicate Transparency；R22 修订）**：

```
where : Predicate × Value × Value → Value
check：cond 的 dtype = bool（E02）+ Σ_cond ⊗ Σ_a ⊗ Σ_b 良式（E03）
ignore：cond 的 layout——谓词根本不进入布局代数（评审 §8：谓词的
        分布是 compiler/backend 的实现关注点，不是 value ownership 语义）
infer：结果 layout = 值侧 merge(a, b)（pairwise，字面量侧无分布）
```

**R-ST（State Update Transparency；R19'/AccumulatorUpdate，v0.6b）**：
ScaleUpdate 的乘数布局免检，累加器布局不变（§2.6 状态表）。

**R-φT（Phi Read Transparency；v0.6b）**：累加器体内读 = 入口值（φ），
定型为布局元变量、出口约束求解（§2.6）；读位收窄为纯值表达式（§1.4）。

- **四条规则的共同点与差异**（评审 §4）：R-BT 是普通纯函数读；
  R-PT 是 control/select 注记（谓词不是值 tile）；R-ST 是 loop state
  transition；R-φT 是 φ/input state 的**时间语义**读
  （`read(acc) = acc_in`）。表面都可简称"读透明"，形式系统里是四条
  rule——以后某个新运算要申请透明，不会出现"它好像只是在读，所以也
  放行"。
- **v0.5 兼容性**：R-BT 在同族场景与 v0.5 的逐轴因子规则结果逐项一致
  （族内因子等价本就成立）；R-PT 在同族场景与 v0.5 三方归并一致——
  **softmax 黄金逐字节不变**（既是回归测试也是等价性证明）。
- **与 v0.2"家族混算 = 隐藏转换 = 显式决策"立场的关系**：该立场针对
  **同形对等混算**（双方都持有全部元素，结果住哪个家族是真决策）——
  保留（E05 照旧）。透明规则针对**主从读取**（一方持有元素、另一方被按
  坐标查阅）——结果归属无歧义（跟着持有方），歧义只在读取代价，而代价
  有界且惯用法中心（H3-C 定量，§2.7）。v0.2-matmul-fragment §3 的表述
  届时加修订注记指向本文（历史文档不重写，房例同 v0.3 对 v0.2 的注记）。
- **哲学表述**：分布是"计算结果的驻留方式"；**读取不改变驻留**。与 R9'
  （store 不查值布局——坐标写的对偶）合成完整原则族：坐标语义的操作对
  分布透明。

### 2.4 R25 full 与种子态：`Zeros(Σ)` → `Seed(Σ)`（更名 v0.6a 已落地；
携带值的 `Seed(value=V)` 扩展仍 v0.6b；评审 §15/§16 采纳）

```
Γ ⊢ sᵢ 静态（INT | constexpr 名）   value 为数值字面量/SpecialValue 且类别与 dt 匹配（E02）
rank ≤ 2    dt ≠ bool
────────────────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.full((s₀,…,s_{r−1}), value, dt) : Tile[dt, (Const(v(sᵢ)),…), Seed((v(sᵢ),…))]
```

- **`Zeros(Σ)` 更名 `Seed(Σ)`**：泛化后 term 描述的是 **type state**
  （"seeded but has no established distribution"），值是多少（0/−inf/1/42）
  属于 `TFull`/`TZeros` 指令的 value semantics，不属于 DistLayout——
  "它根本不应该叫 Zeros"（评审 §15）。**不为黄金稳定坚持错名**：更名随
  v0.6b 落地，`matmul_loop` 黄金一次性再生（仅 TIR 布局定义行
  `zeros(64,128)` → `seed(64,128)`；opcode 与语义零变化）；v0.6a 不触碰
  种子，既有八份黄金在其验收内逐字节不变。
- L7 语义不变：种子态仍是 join 单位元（对 `'+'` 与 maximum——后者经 L2
  广播擦除同样成立）。
- **`ScaleUpdate` 的种子保持是状态转移规则、不是布局律（评审 §16）**：
  "`Seed(0) × L ≡ Seed`" 若写进布局代数，就把 `0·x = 0` 这条**值层**事实
  深度交叉进了**分布层**——更干净的切法是状态机规则：ScaleUpdate 作用于
  零值种子 → `Seed → Seed`（§2.6 状态表；值层理由只出现在规则的前提里，
  不作为 layout law 存在）。**非零值种子 ×**（值 ≠ 0，结果不再全同）
  v0.6b 不开放（E20 MulSeed）——物化语义留待真实消费者。
- **R24 语境来源 +1**：full 的 value 实参按 full 的显式 dtype 定型
  （`full((BM,), 0, f32)` 的 0 即 f32）。
- **seed 值规范化不变量（评审 B-⑩）**：`full(…, 0, dt)` 与 `zeros(…)`
  canonicalize 为**同一** `Seed(value=0)` 状态（checker 按指令的 value
  判定，不是按名字）；`−∞` 种子 → `Seed(value=−∞)`——"值属于指令、状态
  属于类型态"的分层（`TFull → Tile[.., Seed(shape)]`）。

### 2.6 R19 修订：AccumulatorUpdate 状态机、StateRead 元变量（v0.6b）

**状态机（v0.4 §2.1 的推广；携带链实现不变）**：

```
AccumulatorState<S, D, LState>（评审 B-⑤/B-⑧ 正式化；完整 ApplyUpdate
转移表与 seed 值规范化见 `docs/v0.6b-flash.md` §3 B）:
    LState := Seed(value=V) | Materialized(L)
       ↓ 首次 update（状态转移规则）
    Materialized(L)
       ↓ 其后 update
    Materialized(L)

AccumulatorUpdate 的状态转移（按类别）：
    ReduceUpdate  首次：物化 normalize(L_t)（L7 语义）   其后：equiv(L, L_t)（E05）
    ScaleUpdate   Seed(0) × X → Seed(0)——**mul-identity 特例**（0·x = 0；
                  值层事实不进布局代数；不推广为"任意常量种子可 *= "的模糊
                  规则，评审 B-⑨）
                  Seed(V≠0) × X → E20 MulSeed
                  Materialized(L) × X → Materialized(L)（乘数 R-ST 透明）
    HandoffUpdate 首次：物化 x 的 L                     其后：equiv(L, L_x)（E05）
                  （x：当前迭代已定义且**非累加器**的单一局部名——`m = m`
                  自交接 no-op、`m = l` 跨累加器 → HandoffForm，评审 B-⑯）
    （StateRead 不改变状态；φ 的 back 边 = 最后一次 update 的结果）
```

**StateRead 的定型：布局元变量 + 出口约束求解（评审 §14/§27 采纳）**：

1. 累加器 acc 的体内读共享一个**布局元变量 α_acc**；读的静态类型 =
   `Tile[dt, Σ, α_acc]`。
2. α 参与的判定**不立即求值，而是记录约束**：同形 join 记 `α ~ L`；
   广播位/谓词位/乘数位（R-BT/R-PT/R-ST）**不记**——透明位天然不约束
   元变量（四规则与元变量系统的复合是自由的）。
3. 循环收尾：状态机给出 `L_exit`；**赋一 `α_acc := L_exit`**；统一求解
   全部记录的约束——任一失败 → E05。读到的是出口类型（迭代 ≥2 的入口
   = 上一迭代出口），跨族读在此抓获（`y = m + product_local` 的约束
   `α ~ Product` 与 `α := Slice(Mma₁,1)` 冲突 → E05）。
4. 迭代 1 的运行期种子值与一切下游 join 相容由 L7 的**语义**（常量 ⊕
   L ≡ L）覆盖——静态单遍、运行期两态，soundness 不需要前向 typing。
5. 实现可落地为"pending 引用 + 出口回填后统一复检"（检查能力与元变量
   方案等价）；**规范表述取元变量**——它是将来 bidirectional typing /
   constraint 架构（type-system §11 已拒而复召的方向）的第一个真实
   消费者。

**φ 不变量保持**：`type(φ) = type(back)`（v0.4/ast.md 不变量 7 原样）。

### 2.7 桥接假说 H3：语义与代价分离（评审 §9/§10 采纳；oracle 第三轮 §8.1）

Tila semantic layout 与 Triton concrete encoding 本就不是同一个东西——
**convert 计数不判语义生死，只判桥接质量**。H3 拆为两个独立判据：

> **H3-S（语义判定）**：`realize(reduce_k(L))` 稳定对应
> `realize(Slice(L, k))` 的家族结构——reduce-over-dot 结果 encoding 与
> 亲代切片同构（如 `#ttg.slice<{dim=k, parent=<dot-encoding>}>`）、
> `expand_dims` 还原亲代；结论跨实验矩阵（形状 × warps）稳定。
>
> **H3-C（代价判定）**：attention 正则轨迹的 convert_layout 计数
> `C ≤ C_max`（C_max 初拟 4/kernel，dot 操作数入场不计）。

```
H3-S fail          → 分布模型修改：分支六撤回，显式转换通道设计启动
                     （违反 layout 不可见原则的代价被实测正当化），
                     attention 以 3-kernel 流水先行交付（§1.5 fallback）
H3-S pass, H3-C weak → 语义模型保留；桥接代价入档（性能/优化项，
                     不改语言、不触发降级）
H3-S pass, H3-C strong → 完美（0 额外或位置固定少量）
```

判定权在 oracle 第三轮（§8.1）；**H3-S 是 v0.6a 的实现前置门**，H3-C 只
影响记录与优化优先级。**无 Tensor Core 机器（SM 6.1）的边界**：本机 dot
encoding 为 FMA 下探的 blocked 族——H3-S 判定的对象是**结构**（切片/
还原/稳定性），按 encoding 无关设计；mma_layout 的 encoding 级复核待 TC
机器挂起为记录项（H1 先例：FMA 下探的家族分离结论后来无需修正，不阻塞）。

**H3 实验判定（2026-08-24 实测，triton-windows 3.7.1 / TITAN Xp，6/6 组
一致，`tools/oracle_round3_attention.py`，`layout-oracle-notes.md` 第三轮）**：

- **H3-S pass（6/6）**：reduce-over-dot 结果 encoding 恒为
  `#ttg.slice<{dim = k, parent = <dot-encoding>}>`（亲代 = dot 结果
  encoding 本尊）；`tt.expand_dims` 直接返回亲代；跨形状 × warps 稳定。
- **H3-C strong（6/6）**：converts(A/B/C/D) = 1/1/1/1（bn128 组 D=3），
  各 kernel 含 2 dot（入场基线 1/dot）——**入场之外 0–1 次额外**，远低于
  C_max=4。C/D 的全部读透明位点（where-cond 跨族、(BM,1) 广播 join、跨
  Mma rescale、终归一化除法、maximum 链、循环携带）合计 ≤ 1 次 convert。
- **附带核实**：`tl.full` 接受 `float("-inf")`；`tl.maximum` 以
  `arith.maxnumf` 落地、同 dtype 进出无提升。
- 与 H1/H2 的结局**不同且更好**：两轮均为"强形式证伪、家族级成立"，H3
  的结构声明与代价声明**双双原样成立**——因为分支六从一开始就按
  provenance（而非独立等价物）措辞，语义声明与 concrete 行为的缝隙为零。
  **决策表命中完美档：分支六与读透明按设计实现，不降级**；值级正确性由
  GPU 差分独立验收（§8.4）。

## 3. TIR

```
# v0.6a：零新指令（Slice 是 layout term，不进指令集）
# layout 定义行新增形态：
L5 = slice(L3, 1)

# v0.6b：
TFull:       shape: tuple[ConstExpr, …]; value: float|int|SpecialValue; dtype: str
             # opcode: full——常量播种（TZeros opcode 保留：zeros 是 value=0
             # 的既名缩写，指令层不变；更名只发生在布局 term，§2.4）
TMaximum:    lhs: str; rhs: str        # opcode: maximum（与归约 max 分立）
# ScaleUpdate 的 IR 形态 = 普通 mul（opcode 集不膨胀，与 += 是普通 add 同款纪律）
# HandoffUpdate 无指令：φ 的 back 边直接指向被交接的局部值 id
# AccumulatorUpdate 是 tila_ast 语句类别（ReduceUpdate/ScaleUpdate/HandoffUpdate），
# 不是对普通 Assign 的 patch——普通 Assign 保持"SSA 定义"唯一含义（§1.4）
```

dump 示例（attention 片段 + v0.6b flash 片段；expand_dim 按 R13 布局项
不变——(BM,1) tile 的 term 仍是 Slice）：

```
L3 = mma(64,64,64)
L5 = slice(L3, 1)
…
%qk = dot %q2 %k2 : Tile<f32,(64,64),L3> [#qk]
%mx = max %w0 1 : Tile<f32,(64,),L5> [#mx]
%mx2 = expand_dim %mx 1 : Tile<f32,(64,1),L5> [#mx]
…
%m  = full (64,) -inf f32 : Tile<f32,(64,),L4> [#m]          ← v0.6b（种子；L4 = seed(64)）
%m1 = maximum %m.loop %rowmax : Tile<f32,(64,),L5> [#m]      ← v0.6b
```

- `_finalize_ids` / printer / backends 的操作数遍历按既定模式加分支
  （TMaximum 两操作数；TFull 无操作数——与 TZeros 同款）。
- StateRead 引用 φ id（`%m.loop`）；HandoffUpdate 的 φ back 指向局部
  id——printer 的 back 边渲染规则不变。

## 4. Triton lowering

| TIR | Triton |
|---|---|
| `TFull(s, v, dt)` | `tl.full(<shape>, <v>, dtype=tl.<dt>)`（`-inf` 发射 `float("-inf")`；shape 按 ConstExpr 渲染、单元素带尾逗号——zeros 同款） |
| `TMaximum(a, b)` | `tl.maximum(<a>, <b>)` |
| `acc *= t` | `acc = acc * <t>`（φ 不发射；与 `+=` 同款） |
| `m = m1`（HandoffUpdate） | `m = <m1>`（名字直通赋值；loop-carried 归 Triton） |
| Slice 布局 | **不发射任何东西**（透明规则 = 语义层声明；Triton 自行按需 convert_layout，计数由 H3-C 钉死） |

- 其余全部一阶映射；launcher 零改动（无新参数类别；grid 仍 1D
  `ceil(M/BM)`——attention 的 N 轴不建 program 轴，E17 推导输入不变）。
- **待 oracle 附带核实的发射事实**：`tl.full` 接受 `float("-inf")`；
  `tl.maximum` 的 dtype 行为（同 dtype 进出、无提升——若有提升按 v0.5 §4
  纪律显式适配）；跨 Mma 的 `acc * alpha2` 与终归一化除法在 TTGIR 的
  convert 计数。

## 5. Interpreter

- `full`：按 dtype 构造常量数组（`-inf` 用 `np.finfo` 族/`float("-inf")`，
  与 neg_inf 的既有构造同款）。
- `maximum`：`np.maximum`（两侧求值——非严格语义允许）。
- ScaleUpdate / HandoffUpdate：携带值的乘法/直接交接——TFor 的 φ 链机制
  （v0.4 §5）零扩展；**StateRead = `vals[phi]`（入口值）本就是现状**，
  读解禁在 interpreter 侧是"删限制"而非加语义；逃逸位检查是编译期纪律，
  解释器不管。
- 零迭代回退：三个累加器分别回填种子（既有 `setdefault` 机制）；
  N = 0 的 NaN 出口是包络外行为（§1.2）。
- Slice/Seed 布局不影响解释（layout 是静态事实）。

## 6. LaunchPlan：零扩展

attention 的 tiling 惯用法在循环外（`pid * BM + arange`，轴 0）；flash 的
循环内 load 坐标含 `n0 +`——launch analysis 的拍平扫描（v0.4 §6 递归化）
已覆盖循环内模式，且 N 轴不产生 program_id 惯用法（softmax 行耦合——不
切分）。num_programs 等 observational 内建不参与（v0.5 §6 纪律不变）。

## 7. 诊断

**v0.6a：零新码、零新 subcode**（分支六与透明规则只减少 E21/E05 的可达
情形）。E21 ReduceLayout 保留码位（防新布局 term 回归时无声放行），消息
更新为"covered by branch 6 since v0.6; reachable only for future atomic
terms"。

**v0.6b：E20 新 subcode 两个（初拟）+ AccumRead 重新定位**：

| 场景 | subcode | 消息要点 |
|---|---|---|
| handoff 形态违规（RHS 非单一局部名 / 计算表达式 / 目标非累加器 / 体外） | HandoffForm | "handoff is `acc = <local>` on an accumulator inside a loop — a semantic move of state, not a computation" |
| ScaleUpdate 作用于非零值种子 | MulSeed | "rescale-from-seed requires a zero-valued seed (0·x = 0); nonzero full seeds are not multipliable in v0.6b" |
| StateRead 出现在逃逸位（store 实参/mask/coords，含经局部名的传递依赖） | AccumRead（重新定位） | "an accumulator may be read only inside pure value expressions in the loop body; escape via store/return is not allowed (read it after the loop)" |

沿用：ScaleUpdate 体外/目标非累加器/复合表达式重写 → AccumForm（消息
扩展）；handoff 的 dtype/shape 失配 → E02/E03；StateRead 元变量约束冲突
→ E05（§2.6）。
