# v0.3 设计：stride 化 MemoryLayout（坐标寻址）

状态：定稿（2026-08-24）。前置：v0.1（`type-system.md`）、v0.2 预览（`v0.2-preview-2d.md`）、
v0.2 matmul fragment（`v0.2-matmul-fragment.md`）。本文是该三项的实现推进，不修改
其中已冻结的 dtype/layout 代数语义。

---

## 0. 动机：手工线性化盲区（两次实证）

v0.1/v0.2 的寻址模型是**平面线性偏移**：`b + offs`，offs 是把多维坐标手工乘加出来的
i32 tile。matmul fragment 实现期间出过一次类型全对、结果全错的 bug：

```python
b_idx = rk3 * K + rn2        # B 是 (K,N) 行主序：正确是 rk3 * N + rn2
```

checker 全绿（`rk3 * K + rn2` 是完全良式的 i32 tile 运算），错误由 interpreter 差分
当场抓获。这不是实现疏漏，是**模型缺陷**：内存布局知识（"b 的第 0 维步长是 N"）
写在**使用点**而不是**声明点**，类型系统无从核对。`v0.2-preview-2d.md` §6 已把它列为
残余盲区，`development-plan.md` §11.4（维度绑定索引）是它的 v0.3 候选方案之一。

本设计采取更彻底的路线：**strides 进类型、线性化归编译器**。维度绑定索引把布局知识
留在使用点做检查；strides 把布局知识搬进 Buffer 类型，使用点只剩坐标——没有可写错
的东西。两者不冲突：维度绑定索引将来可叠加在坐标形式之上（核对坐标语义，不管布局）。

**不变量（本设计的全部内容围绕它）**：

> 用户表达"要哪一块"（逐轴坐标），Buffer 声明"数据怎么摆"（strides），
> 编译器拥有"坐标 → 线性地址"的线性化。表面上不再出现任何 `r * stride + c`。

由此得到一条语言哲学（升为原则；评审 §5 采纳）：

> **地址运算发生在 logical coordinate space，而不是 linearized index space。**

## 1. 表面语法

### 1.1 注解：strides 尾随元组

```python
b: tila.Tensor[tila.float16, K, N, (sb0, sb1)]   # strides 元组：每轴一个 INT 或符号名
a: tila.Tensor[tila.float16, M, K]               # 省略 = 隐式 RowMajor（v0.1 语义不变）
```

文法扩展（`language-spec.md` §4 的增量）：

```
tensor-ann   ::= "tila.Tensor[" dt dim+ strides? "]"
strides      ::= "(" stride ("," stride)* ","? ")"     # 只允许作最后一个下标项
stride       ::= INT | IDENT
```

- **为什么是尾随元组而不是 `strides=(sb0, sb1)`**：Python 下标**不支持关键字参数**
  （`x[a, k=v]` 是 SyntaxError；PEP 637 从未被接受）。注解经 `ast.parse` 再解析，
  关键字形式在 parse 期即死。尾随元组是 `ast.Tuple`，天然可解析、与 dim 语法
  （INT|IDENT）结构性区分、无歧义。
- **为什么允许全符号 strides（不强制末轴为 1）**：非连续张量（转置、padding、切片）
  的末轴步长不必是 1。正确性是类型系统的职责，coalescing 质量是性能问题——与 mask
  哲学同款分工（`type-system.md` §0 原则 5：显式表达，不替用户做性能决策）。
- 静态 INT stride 必须 ≥ 1（0/负数 → E12）。符号 stride 的正性不做静态约束
  （约束系统是 §2.1 assume 时代的事），运行期值错 → 结果错，与 mask 越界同级：
  类型系统保证"按声明的步长寻址"，不证明"声明的步长符合张量实情"——后者由
  launcher 断言兜底（§6）。

### 1.2 寻址：load/store 一级坐标原语（v0.3 定稿）

内存 API 统一为两个一级原语，坐标元组是其第 2 位置实参：

```python
x = tila.load(a, (rm2, rk2), mask=a_m, other=0.0)   # 逐轴坐标 tile，长度 = buffer rank
y = tila.load(b, (rk3, rn2), mask=b_m, other=0.0)
offs = pid * BLOCK + tila.arange(0, BLOCK)
z = tila.load(a, (offs,), mask=m)                   # rank-1：单元素元组（统一形态）
tila.store(c, (rm2, rn2), acc, mask=c_m)
```

- **语义模型直接成为语法**：`load(buffer, coords)` 说的就是"从 b 的逻辑坐标
  取数"——坐标 → 地址的线性化完全 compiler-owned，表面语言**没有任何地址
  算术**（`a + offs` / `a + (i, j)` 旧形式整体移除；独立出现 → E07，旧
  load/store 实参形态 → E13 附迁移提示）。**Address 由此彻底内部化**：它只在
  checker 内部（load/store 检查中）构造，用户不可见、不可命名。
- 坐标元组**只允许出现在 load/store 的第 2 位置实参**（转换期语法约束）；
  其它任何位置的元组 → E11（不属于子集），保持"元组不是 Tila 值"。
- 元组长度必须等于 buffer rank（≠ → E19 CoordinateArity）；每个坐标必须是
  i32 tile（标量 → E19 CoordinateKind：坐标位混入 Scalar 会引入隐式广播，
  这是设计约束而非暂缺，§9）。

**被拒的替代语法**：

| 方案 | 拒绝理由 |
|---|---|
| `strides=(sb, 1)` 关键字 | Python SyntaxError（上文）；不评估 |
| `b[rk, rn]` 下标 | v0.1 起下标就整体排除在子集外（E11） |
| `tila.addr(b, rk, rn)` / `a.at(...)` 内建 | 制造可命名的 Address 值——与"地址计算归编译器"矛盾 |
| `a + (rm, rk)`（初版 v0.3 形式） | 曾采纳（与 R7/Triton pointer mental model 一致、迁移体验好）；定稿评审撤销——它把 coordinate → address 伪装成算术运算，`load(buffer, coords)` 才直接暴露语义模型（第三轮处置，§11） |
| `tila.load(b + offs)` 平面形式 | 手工线性化盲区本体（§0）；随 `+` 寻址一并移除 |

### 1.3 Address Function（数学锚点；评审 §21 采纳）

MemoryLayout 的语义是一个**地址函数**（AddressMap），不是 layout 代数 term：

```
L : (i₀, …, i_{r−1}) → offset

RowMajor(shape)：   L(i) = Σᵢ iᵢ · (∏_{j>i} d_j)        （rank ≤ 2：i₀·d₁ + i₁）
Strided(s)：        L(i) = Σᵢ iᵢ · sᵢ

Address(b, c) = base(b) + L_b(c)
```

- **`base(b) = 逻辑张量原点`（ABI 规则，写死）**：不是底层分配的起点。torch 侧
  `data_ptr()` 天然含 `storage_offset`；numpy 侧逻辑索引天然正确。**stride 正确
  ≠ storage offset 正确**——偏移由 ABI 吸收，kernel 侧不可见（测试覆盖连续/
  转置带偏移视图，numpy + GPU）。
- TIR（`addptr` 携带坐标）、interpreter（逻辑索引实现同一函数）、Triton lowering
  （发射 `L_b(c)` 的文本）、launcher（契约断言）**全部从这一定义派生**；逐轴系数
  的代码事实源是 `types.layout.strides_of`（§5）。
- 这也是将来 TMA / swizzle / blocked memory 的接入点：新的 MemoryLayout =
  新的 `L`，地址语言与坐标语义都不用动。

## 2. 类型层

### 2.1 MemoryLayout 文法（`type-system.md` §3.1 的 v0.3 修订）

```
M ::= RowMajor            # 隐式默认：不物化 stride 表，lowering 从运行期 shape 计算
    | Strided(strides)    # 显式声明：strides : (Const | Symbol, …)，len = rank
```

- `RowMajor` 保留为独立 term 而非 sugar 到 `Strided((d₁, …, 1))`：rank ≥ 3 的默认
  行主序需要 `d₁·d₂` 这类**符号乘积**——那是 DimExpr 阶段二的非线性项。v0.3 rank
  上限仍为 2（rank-2 默认 strides = (d₁, 1)，d₁ 是符号或常量，无乘积），rank ≥ 3
  随 rank 解禁再议（§9 范围外）。运行期表达式（生成的 Triton 里出现乘法）与类型层
  DimExpr 是两回事——乘法可以随时出现在生成的代码里，永远不进类型层。
- **M 不参与等价判定**：DistLayout 有 equiv/normalize，MemoryLayout 没有——它是
  per-Buffer 的事实，两个 Buffer 类型从不互相 unify，无从比较。这是两层的又一处
  不对称（语义侧代数 vs 内存侧事实）。
- `TensorAnn` 增加 `strides: Optional[(StaticDim|SymDim, …)]`；`BufferType` 打印在
  Strided 时追加 `strides=(sb0,sb1)`（RowMajor 不打，1D 黄金字节不变）。

### 2.2 stride 符号绑定与符号宇宙

**符号宇宙二分（评审 §9/§11 采纳）**：符号分两类——`DimSymbol`（来源
`shape[i]`）与 `MemorySymbol`（来源 `stride[i]`），共用同一张符号表（checker 的
`SymBinding`：kind + 首次绑定来源 buffer/axis）。两者都是"运行期需物化的编译期
符号"；统一符号表是将来 `assume` / 约束系统（`type-system.md` §2.1）的挂接点。

stride 元组里的 IDENT 按现有 sym 规则绑定（`type-system.md` §4）：

- 已绑定的符号（任一注解的维符号）→ 引用之：`Tensor[f32, K, N, (N, 1)]` 是显式
  行主序——`strides=(N,1)` 里的 N 是 **symbol identity relation**（sb₀ ≡ N，
  同一运行期量），不是新符号。launcher 断言 `stride(0) == N`，张量实际非连续则
  断言失败（用户应改用独立符号）。**一个符号、一个运行期值**。
- 新名字 → 自动绑定为运行期 `Scalar(i32)` 参数（launcher 从 `tensor.stride(i)` 读取），
  跨 buffer 共享时断言一致——与符号维同款契约（`semantic-model.md` §7）。
- 名字冲突检查沿用 E12（与参数名/constexpr 名/保留名互斥；冲突信息标注符号类别）。

符号收集顺序：按参数签名序，每个参数先维后 stride——例：`a: Tensor[f16, M, K]`、
`b: Tensor[f16, K, N, (sb0, sb1)]` → sym 序 `M, K, N, sb0, sb1`。

### 2.3 寻址规则（type-system R8/R9 的 v0.3 前提；原 R7/R7' 内部化）

```
Γ ⊢ b : Buffer[dt, Σ_B, M]     Γ ⊢ tᵢ : Tile[i32, Σᵢ, Lᵢ]（i = 0..r−1）   r = rank(Σ_B)
坐标元组长度 = r     Σ = Σ₀ ⊗ ⋯ ⊗ Σ_{r−1} 良式
───────────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.load(b, (t₀,…,t_{r−1}), …) 的寻址前提 : 内部 Address[dt, Σ, 坐标广播推导]
```

- **Address 是 checker/TIR 内部类型**：由 checker 在 load/store 检查中构造
  （`buffer_address`），表面语言不可见、不可命名——原 R7（平面 `+`）与初版
  R7'（`buffer + coords`）作为**表面规则**均已移除，寻址前提并入 R8/R9
  （第三轮处置，§11）。
- 坐标 tile 各自任意 rank（典型形态：`(BM,1)` 与 `(1,BN)`）；Address shape =
  坐标广播积，layout 推导复用 v0.2 的 `broadcast_layout`（Product 配对 /
  JoinL 擦除，与 R14 同款）。**不发明新的布局机制**。
- dtype 链：坐标非 i32 → E02；坐标间不可广播 → E03；坐标元组长度 ≠ rank、
  第 2 实参不是元组、标量坐标 → **E19**（§7）。
- 与 R9' 正交：strides 在内存侧（Address → 元素），dot 的家族切换在分布侧
  （Tile → Tile）；`tila.store(c, (rm2, rn2), acc)` 里 acc 的 Mma 分布与 c 的
  strides 互不过问——内存边界布局无关的既定语义原样成立。

## 3. TIR

```
TAddPtr: base: str, coords: tuple[str, …]     # 1 + rank(b) 个坐标引用
```

- dump：单坐标 `addptr %a %offs`（**与 v0.2 逐字节相同**）；多坐标
  `addptr %b [%rm2, %rn2]`（方括号逗号表）。
- 线性化**不进 TIR**：addptr 保持"buffer + 坐标"的语义形态，lowering 与
  interpreter 各自从 kernel 参数表查 base 的 MemoryLayout 完成线性化。理由：
  (a) stride 的唯一事实源是 BufferType（单一来源），物化成 TIR 算术会复制事实；
  (b) TIR dump 保持可读的坐标语义；(c) 未来 TMA / swizzle 的 lowering 变体直接
  挂在 addptr 上，不必重写算术链。
- `_finalize_ids` / printer 的操作数遍历覆盖 coords 元组（机械）。

## 4. Triton lowering

### 4.1 addptr 发射（`triton-lowering.md` §5 的 v0.3 修订）

```
base + (c₀*s₀ + c₁*s₁ + …)        # 多坐标：偏移整体加括号
base + offs                        # rank-1 RowMajor：无乘法、无括号（v0.2 字节不变）
base + (offs * s₀)                 # rank-1 Strided
```

stride 项来源：`Strided` → 声明值（Const 渲染字面量、Symbol 渲染参数名）；
`RowMajor` → 运行期 shape 计算（rank-2：`(d₁, 1)`，d₁ 按声明渲染——符号维名或
静态字面量）。

matmul 例（b 全符号 strides）的生成代码：

```python
x = tl.load(a + (rm2 * K + rk2), mask=a_m, other=0.0)
y = tl.load(b + (rk3 * sb0 + rn2 * sb1), mask=b_m, other=0.0)
acc = tl.dot(x, y)
tl.store(c + (rm2 * N + rn2), acc, mask=c_m)
```

### 4.2 launcher（stride 提取与断言）

生成序：rank 断言 → 静态维断言 → 维符号绑定/共享断言 → **stride 绑定/断言** →
grid → 调用。stride 规则逐轴：

| 声明 | 发射 |
|---|---|
| Const(n) | `assert b.stride(i) == n` |
| Symbol（首次绑定，非 dim 复用） | `s = b.stride(i)` |
| Symbol（跨 buffer 共享） | `assert c.stride(i) == s` |
| Symbol == 某维符号（dim 复用） | `assert b.stride(i) == <该维符号>`（其值已由 shape 绑定） |

matmul 例：

```python
def matmul_launch(a, b, c, M, K, N, sb0, sb1, BM=64, BN=128, BK=64):
    assert a.dim() == 2 and b.dim() == 2 and c.dim() == 2
    M = a.shape[0]
    K = a.shape[1]
    N = b.shape[1]
    sb0 = b.stride(0)
    sb1 = b.stride(1)
    grid = (triton.cdiv(M, BM), triton.cdiv(N, BN))
    matmul[grid](a, b, c, M, K, N, sb0, sb1, BM=BM, BN=BN, BK=BK)
```

torch 的 `Tensor.stride()` 返回**元素步长**，与声明语义一致。**非连续张量由此
解锁**：`b = torch.randn(N, K).t()`（shape (K,N)、strides (1,K)）直接可传——
这正是本设计的验收场景。

**RowMajor（省略 strides）同样是内存布局声明，不是"无所谓"**：launcher 对每个
RowMajor buffer 发连续性断言（rank r：`stride(r−1) == 1` 且 `stride(i) ==
shape[i+1]`；全部走 `b.shape[...]` 自足表达式，不依赖符号绑定顺序）——非连续
张量喂给默认声明的 buffer 在断言处显式失败，而不是静默读错元素（那正是本版本
要消灭的错误类别）。因此**全部** launcher 产物（含 1D）新增一行合并断言；
1D 的 TIR dump 与 kernel 体逐字节不变，黄金按此再生成。
（v0.4 修订：size-0 数组的契约空真——每个 RowMajor 断言带
`<b>.numel() == 0 or (…)` 守卫，见 `v0.4-kloop.md` §12。）

**RowMajor 的期望步长永远由 shape 推导**（rank-2：(d₁, 1)——§1.3 的 `L_row`），
运行期实际步长**只用于契约检查，绝不用于布局推断**：

> **MemoryLayout is declarative, not inferred.** 声明 RowMajor 而传入转置张量
> 是契约违反（拒绝），不是"编译器自动识别为转置"——那会让类型声明失去
> contract 意义（stride 推断不做的根本理由，§9）。

## 5. Interpreter

- **访存走逻辑多维索引，不走平面偏移**：既然 stride 契约已断言（声明值 == 实际
  元素步长），"按声明步长访存"与 `arr[c₀, c₁, …]` 严格等价；而逻辑索引对任意
  布局的 numpy 视图都正确——`reshape(-1)` 对非连续数组会**按逻辑序拷贝**，平面
  偏移模型在视图上反而失真（实现期间实证：转置 b 上平面模型产出错值）。GPU 侧
  按声明步长真访存，两侧由等价性 + 同一契约对齐。
- **RowMajor 连续性断言**：声明默认行主序的 buffer 收到非连续数组 → 拒绝
  （与 launcher 同款契约）。静默接受会让 interpreter"看似正确"而 GPU 读错
  元素——双路径分歧，差分测试立刻暴露，但直接拒绝更好。
- **stride 符号取值**：与维符号同款——首绑定 buffer 的 `stride(i)`（numpy 需
  `arr.strides[i] // arr.itemsize` 换算成元素步长）；跨 buffer 共享 / dim 复用
  断言一致。LaunchPlan 携带 stride 绑定表供双路径共用（§6）。
- **事实源共享、执行不共享**（评审 §22 的采纳方式）：逐轴系数的唯一事实源是
  `types.layout.strides_of`（§1.3 的 `L`）；lowering 由它发射文本，interpreter
  以逻辑索引实现同一函数（等价性由契约保证）。**不**把 interpreter 改成"求值
  同一棵 AddressExpr"——那会重新落回平面模型在 numpy 视图上的失真（下条实证）。
- addptr 求值保持 `(base, coords)` 惰性形态，线性化完全推迟（不进 TIR，§3）。

## 6. LaunchPlan 扩展

```
stride_bindings: ((buffer, axis, int|sym), …)     # Strided buffer 逐轴，声明序
```

- checker 签名阶段收集（Strided 才有）；lowering 只发射、interpreter 只取值——
  维持"launch plan 是运行期契约的唯一载体"。
- 维符号绑定表（既有 `sym_dim_asserts`）与 stride 绑定表共同覆盖全部 sym 参数：
  launcher 对每个 sym 参数二选一取值（shape 或 stride），无第三来源。

## 7. 诊断：E19 AddressForm（新增）

| 场景 | 消息要点 |
|---|---|
| load/store 第 2 实参不是坐标元组（如 `tila.load(a, offs)`） | "coordinates must be a tuple literal with one i32 tile per axis: tila.load(a, (offs,))" |
| 坐标元组长度 ≠ buffer rank | "coordinate tuple has n entries but buffer 'b' has rank r" |
| 标量坐标（`tila.load(b, (rows2, 5))`） | "each coordinate must be an i32 index tile" |
| 坐标 tile 非 i32 | E02（dtype 链） |
| 坐标间不可广播 | E03（shape 链） |
| 旧形式 `tila.load(a + offs)` | E13（实参数量），消息附迁移提示；独立出现的 `a + offs` 算术 → E07 |
| 元组出现在其它任何位置 | E11（转换期；元组不是值） |
| 注解：strides 元组长度 ≠ rank、INT stride < 1、strides 元素非 INT/IDENT | E12（注解链） |

分工纪律：E19 只管**寻址形态**；dtype/shape 仍走 E02/E03（`type-checker.md` §7
的 E07 不做垃圾桶原则同款适用）。

**subcode（评审 §26 采纳，随第三轮 API 定稿更新）**：E19 内部细分——
`CoordinateForm`（第 2 实参不是元组）、`CoordinateArity`（元组长度 ≠ rank）、
`CoordinateKind`（坐标非 i32 tile）、`CoordinatePosition`（防御位：元组出现在
load/store 之外的位置）。渲染仍显示 `E19`（用户视角不变）；`TilaError.subcode`
供测试矩阵与内部分派。

## 8. 测试计划

1. **黄金**：strided matmul / batched_add 的新 TIR + Triton 快照；**1D 的 TIR
   dump 与 kernel 体逐字节不变**（add/saxpy/masked_add/fp8_add——rank-1 平面
   形式不变的回归证明），launcher 各增一行连续性断言后全部再生成。
2. **E19/E12 矩阵**：上表逐场景 + 注解错误（strides 长度错、负 stride、strides
   符号撞参数名）。
3. **差分（本设计的验收主场）**：
   - interpreter vs GPU vs torch 参照，matmul/batched_add；
   - **非连续张量**：`b = randn(N,K).t()`（strides (1,K)）、padded 存储
     （`base[: , ::2]` 之类）——声明式 strides 下结果必须正确，这是 v0.2 做不到的；
   - dim 复用 `(N,1)` 注解 + 传入非连续张量 → launcher 断言失败（正确拒绝）。
4. **launcher 单元**：符号 stride 绑定顺序、跨 buffer 共享断言、静态 stride 断言。

## 9. 范围外（显式不做）

| 项 | 理由 |
|---|---|
| rank ≥ 3 的默认 RowMajor stride 物化 | 需要 `d₁·d₂` 符号乘积（DimExpr 非线性项）；rank 上限本身仍是 2。`RowMajor` 保持语义原语（§1.3 的 `L_row` 按 shape 定义），不物化成 Strided 项 |
| 标量坐标（`tila.load(b, (rk, 5))`） | **设计约束而非暂缺**（评审 §19）：坐标元组里混入 Scalar 会立即引入隐式 scalar→tile 广播——正是语言拒绝的 implicit semantics；要用 tile（`expand_dim` 可造 size-1 轴） |
| constexpr / DimExpr stride 表达式 | strides 先只有 INT\|IDENT；表达式随 §2.1 分阶段放开 |
| stride 推断（不声明则从张量自动绑定） | **MemoryLayout is declarative, not inferred**（§4.2）：不声明就是 RowMajor，错配在 launcher 断言处显式失败——静默推断会把错误推迟到更难诊断的地方，且让类型声明失去 contract 意义 |
| 负 / 零 stride | 语义上可表示（`x[::-1]` 即负步长），v0.3 **刻意排除**而非不可表达——将来支持 reverse view 不是推翻设计（静态 <1 已 E12；符号正性留给 assume） |
| `tila.load(b, coords=(r, c))` 关键字坐标 | 已由位置元组形态 `tila.load(b, (r, c))` 取代（第三轮定稿即是该评审建议的位置实参版本） |
| 符号 stride 正性约束 | 约束系统是 assume（§2.1 阶段二）的事 |
| TMA descriptor / swizzle MemoryLayout | 桥接问题的后续；接入点即 §1.3 的新 `L`，term 位置由 M 文法预留 |

## 11. 评审意见处置（2026-08-24，v0.3 review）

外部评审结论：架构 / surface syntax / TIR 设计赞成；风险集中在 MemoryLayout
"事实属性"与符号系统、runtime contract 的交界。逐条处置：

**采纳（本轮落地的条文与代码）**：

- **Address Function 形式化**（§1.3 新增）：`Address(b, c) = base(b) + L_b(c)`
  是整个内存模型的数学锚点；TIR / interpreter / lowering / launcher 全部从它
  派生。代码事实源 = `types.layout.strides_of`（printer 改用它，删除私有重复
  实现；新增单元测试钉住系数推导）。
- **术语正交**：DistLayout（分布，等价代数）与 MemoryLayout（内存，地址函数）
  严格分名，禁用泛化的"layout"（`type-system.md` §3 记法约定）。
- **符号宇宙二分**：DimSymbol / MemorySymbol 共用一张符号表——checker 的
  `env.syms` 从裸名升级为 `SymBinding(kind, buffer, axis)`（§2.2）；
  `stride = N` 是 symbol identity relation。
- **E19 subcode**：FlatAddressing / CoordinateArity / CoordinatePosition /
  CoordinateKind（渲染不变，`TilaError.subcode` 供测试，§7）。
- **storage offset ABI**：`base(b) = 逻辑张量原点`写死（§1.3）；新增连续/转置
  带偏移视图的差分测试（numpy + GPU）——"stride 正确 ≠ storage offset 正确"。
- **RowMajor 语义精确化**：期望步长永远由 shape 推导、实际步长只做契约检查，
  "MemoryLayout is declarative, not inferred"（§4.2）。
- RowMajor 是 **semantic primitive** 而非 Strided 的语法糖（§2.1/§9 重申）；
  负步长"语义可表示、刻意排除"（§9）；标量坐标的拒绝升格为设计约束（§9）；
  "地址运算发生在 logical coordinate space"升为语言哲学（§0）。

**部分采纳**：

- **共享 linearizer**（评审 §22）：采纳"单一事实源"（`strides_of`），不采纳
  "interpreter 求值同一棵 AddressExpr"——平面模型在 numpy 视图上按逻辑序拷贝
  而失真是实现期实证（§5）；逻辑索引才是 Address Function 在 reference 语义
  下的正确实现，等价性由 stride 契约保证。
- **LaunchPlan 重构为统一 bindings 模型**（评审 §13）：概念采纳——shape 绑定
  与 stride 绑定是同一概念（"运行期需物化的编译期符号"），符号表已统一
  （SymBinding）；LaunchPlan 的具体四元组结构保留，重命名只震荡 golden 与
  消费方而无语义增益。

**拒绝**：

- **elaboration 期把 `+` 区分为 PtrAdd 节点**（评审 §6）：平面形式
  `b + offs` 在脱糖期无法判定 lhs 是否 buffer（那是类型信息）；坐标形式已有
  IndexTuple 语法标记 + checker 前置分派。评审想要的"区分"在 TIR 层已经存在
  （`addptr` 是独立 opcode，不是 Add）——AST 层保持单一 `+` 文法。
- **`b[rk, rn]` 下标进语言**：v0.1 起下标整体排除；`load(b, coords=…)` 记为
  未来第二拼写候选（§9）。

## 12. 第三轮处置：memory API 定稿（2026-08-24，用户裁决）

第二轮评审（§11）之后的外部建议 + 用户裁决：把 `a + (rm, rk)` / `a + offs`
改为**一级坐标原语**，整个 memory API 统一为：

```
tila.load(buffer, (c₀, …, c_{r−1}), mask=?, other=?)
tila.store(buffer, (c₀, …, c_{r−1}), value, mask=?)
```

**采纳并落地**：

- **语义模型直接成为语法**：`load(buffer, coords)` 不再把 coordinate → address
  伪装成算术运算；这是对不变量（§0）最直接的表面表达。rank-1 同为单元素
  元组 `(offs,)`——统一形态，无特例。
- **Address 彻底内部化**：表面规则 R7/R7' 移除，寻址前提并入 R8/R9（§2.3）；
  checker 内部以 `buffer_address` 构造，用户不可见、不可命名。
- **TIR / lowering / launcher / interpreter / 黄金零改动**：addptr/load 的 IR
  结构不动，六份黄金快照逐字节不变——这是一次纯表面定稿，语义链
  （§1.3 Address Function）原样。

**裁决记录**：初版 `a + (rm, rk)` 的优势是 Triton 迁移体验（pointer mental
model 同形）；定稿取"语言自身语义最干净"——迁移体验损失由 E13/E07 的迁移
提示补偿（旧写法给出明确改写建议）。

**拒绝**：`a.at(rk, rn)` / 可命名 Address 值（与"地址计算归编译器"直接矛盾）。
