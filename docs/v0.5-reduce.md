## 0. 动机：语言需要第二个 kernel 形态

v0.4 之后 Tila 能写"乘加"（matmul），但写不了"激活归一化"——softmax /
layernorm / attention 的公共内核是**逐元素数学 + 轴内归约**：

```
softmax 行算法：  m = max_row(x) → e = exp(x − m) → s = sum_row(e) → y = e / s
```

三个缺口：没有 `exp`（一元数学）、没有 `sum/max`（轴归约）、掩码列不能干净地
排除出归约（`where`）。v0.4 的 `+=` 已被定义为 reduction update primitive
（v0.4-kloop §13）——**tile 内轴归约是归约故事的另一半**。

**验收载体 = softmax**：第一个非 matmul 形态的完整 kernel，人人可对照
`torch.softmax` 验证；它同时是 v0.6 attention（`softmax(QK^T)·V`）的前置。

**不变量（本设计的全部内容围绕它）**：

> 归约销毁轴，也只销毁轴：shape 丢一维、分布取边缘（幸存轴保留自身分布）、
> dtype 不变（无隐式提升——**backend 显式适配 Triton 的提升策略，§4**）。
> 逐元素内建与 where 一律**保持或归并**分布——整个 softmax 的 layout 轨迹
> 被约束在 Product 族内闭环。

本设计真正交付的是**五个语义原语**（评审 §25 的框架，采纳）——七个 API
只是它们的表面拼写：

```
1. Elementwise Map        exp / exp2 / sqrt / abs
2. Broadcast Select       where（三方广播 + 值选择）
3. Axis Reduction         sum / max（边缘化）
4. Program Context Query  num_programs（只读观测）
5. Contextual Literal     0.0 / tila.neg_inf 按语境定型（R24）
```

由此得到核心新规则——**归约 = 分布的边缘化**（marginalization，§2.1）：
这是 dot 之后第二个触碰桥接问题的运算，配套 oracle 实验第二轮（§8.1，
桥接假说 **H2**）。从 v0.5 起，"abstract distribution semantics ↔ Triton
concrete layout"正式成为本项目的主要研究问题（评审 §28，采纳）。

## 1. 表面语法

### 1.1 轴归约：sum / max

```python
m = tila.max(x, axis=1)      # (BM, BN) → (BM,)   丢轴降 rank（Triton 同款）
s = tila.sum(e, axis=1)      # (BM, BN) → (BM,)
```

- **丢轴降 rank，无 keep_dims 特例**：要升维用既有的 `tila.expand_dim`
  （`m2 = tila.expand_dim(m, 1)`）——softmax 的广播惯用法本就需要它。
- `axis` 是 **INT 字面量**（编号 x 自身轴；constexpr 名亦可——特化值），
  位置实参或唯一 kwargs `axis=`；其它形态 → E13。
- **rank 恒为 2**（v0.5）：rank-1 全归约（→ Scalar）与 rank ≥ 3 都 →
  E21（§9 各有理由）。
- **结果 dtype = 输入 dtype，无隐式提升（Tila 语义）**：f16 进 f16 出。
  softmax 的正确姿势是入口即 `cast` 到 f32 算完再 cast 回（与 Triton 教程
  一致）——强类型语言不替用户决定精度（与"无隐式收窄"同款哲学）。
  **这不是对 Triton 行为的转述，而是 Tila 的语义合同**：实测 Triton
  3.7.1 中 `tl.sum` 对 int<32 默认提升 i32/u32 返回、`tl.max` 对一切
  <32 位 dtype 内部提升 f32/i32 返回——lowering 必须显式适配（§4 适配
  表；评审 §5 采纳）。累加精度 = 结果 dtype（f16 行和就是 f16 累加，
  溢出/精度是用户显式选择；要 f32 累加就先 cast——与整数回环同权）。
- dtype 能力门：`sum` 走 `'+'` 能力、`max` 走 `'<'`（比较）能力——fp8 →
  E16（storage-only），bool → E16（掩码来自比较）。整数归约合法。
- **归约零元表**（Reduction identities，评审 §13 采纳——先入表、后消费）：

  | op | 零元 | 状态 |
  |---|---|---|
  | sum | `0` | 已开放（v0.4 `zeros` 种子即它的物化——`+=` 播种机制的零元一致性是 v0.4 设计的隐含前提，此处显式化） |
  | max | `−∞` | 已开放（`tila.neg_inf`，§1.3；跨迭代 running max 需非 zeros 种子，v0.6） |
  | min | `+∞` | 未开放（零元先入表） |
  | prod | `1` | 未开放（同上） |

### 1.2 一元数学族：exp / exp2 / sqrt / abs

```python
e = tila.exp(x - mx2)        # 逐元素；layout 保序（律 L8）
```

- 能力表进 `arithmetic.py` 的机器可读风格（UNARY 表，§2.2）：

  | op | f16 | bf16 | f32 | f64 | int | bool/fp8 |
  |---|---|---|---|---|---|---|
  | exp / exp2 / sqrt | ✓ | ✓ | ✓ | ✓ | E16 | E16 |
  | abs | ✓ | ✓ | ✓ | ✓ | ✓ | E16 |

  `abs` 进首发集（评审 §24 采纳）：它是 int+float 双域成员，使 UNARY
  能力矩阵从"全员 float-only"变为真实矩阵——能力表机制当场受到检验，
  而成本仅一列。
- 结果 dtype = 输入 dtype；**layout 保序 = 规则本身**（律 L8，§2.2）。
- 首发集合 **{exp, exp2, sqrt, abs}**：机制表驱动，家族其余成员（log /
  rsqrt / floor / …）走同一规则 R21 与能力表追加，**不另立设计**（§9）。

### 1.3 where：select 形态的条件值

```python
neg = tila.where(m2, x, tila.neg_inf)     # 掩码列不进 max
z = tila.where(m2, e, 0.0)                # 掩码列不进 sum
y = tila.where(m2, e / s2, 0.0)           # 掩码行不产生 NaN
```

- **这是 v0.4 评审 §21 背书的路线**：语言不引入 `if` / CFG，条件值用
  select 形态表达。`where` 是它落到表面的第一步。
- 三实参：`cond` 为 `Tile[bool]`；`a`/`b` 为 **Tile 或字面量/特殊常量**
  ——softmax 的掩码惯用法高度依赖字面量分支（`0.0`、`tila.neg_inf`；
  `other=` 的 where 版）。字面量分支按**语境定型**（R24，§2.6）：以
  Tile 侧的 dtype 为期望，`0.0` 直接定型为该 dtype——**不是**
  f64-再-隐式收窄（评审 §7 采纳）。a/b dtype 两侧严格相等（E02），
  两 Tile 分支或 Tile⊕字面量；两个都是字面量无意义 → E13。
- shape：`Σ = Σ_cond ⊗ Σ_a ⊗ Σ_b` 三方广播良式（E03）——**R14 的 n 元
  推广**，逐轴取非平凡侧。
- layout：`merge_nontrivial` 逐轴归并（§2.3 形式化——评审 §9 采纳）：
  每轴取 size ≠ 1 提供者（非平凡侧）的因子；**双侧非平凡则要求
  equiv，否则 E05**；全平凡轴 → `Identity(1)`；字面量侧不携带分布
  （与 R4 标量侧同地位，BcastScalarL 平凡化后 L2 擦除）。**无新布局
  机制**，实现即 pairwise 折叠（严格退化为 R14 的 `broadcast_layout`）。
- **`tila.neg_inf`（新表面常量；评审 §12/§20 采纳）**：裸属性（非调用、
  非字面量语法扩展——Python 一元负号 hack 不进 surface），语义 = 最小
  可表示浮点值（−∞）。语境定型规则与浮点字面量同款（float 族期望 →
  该 dtype；独立出现 → f32）。它是 max 的归约零元（§1.1 表）与掩码
  max 惯用语的正确哨兵——**`-1e30` 方案被否决**（见 §1.6 拒绝表）：它
  依赖"真实数据 > −1e30"的隐式假设，对 f32 存储的合法输入
  （如 −3e38）会污染 max；Triton 官方 max 示例同样使用 `-inf` 哨兵。
- **非严格语义**（评审 §21 采纳）：where 只规定
  `resultᵢ = cᵢ ? aᵢ : bᵢ`（逐元素值选择）；**不规定未选分支是否求值**
  ——`0/0 → NaN` 等未选侧现象不可依赖，backend 可自由优化（select /
  cmov / 分支均可）。interpreter 的 errstate 处理对应"浮点异常不可
  观察"（§5）。

### 1.4 num_programs

```python
nblk = tila.num_programs(0)         # : Scalar(i32)——当前 grid 的该维大小
```

- R1（program_id）的同款小件：axis 为字面量 / constexpr 特化值 ∈ {0, 1}
  （grid rank ≤ 2 时代），否则 E13。
- **只读不建轴（observational）——正式语义句**（评审 §11 采纳）：
  `num_programs` 观测 launch 配置、**永不参与 launch 推断**（不产生
  E17、不改变 grid 判定）；grid 仍只由 `program_id` 的 tiling 惯用法
  推导。对未被 `program_id` 建立的轴，返回实际 launch 该维的值
  （Triton 对未发射维补 1）。persistent kernel / split 校验是它的未来
  消费者。与 `program_id` 同属 **program-context query 类内建**——
  不是 dataflow 操作，而是执行上下文查询（评审 §22 采纳，
  language-spec 内建表增设分类列）。

### 1.5 目标程序：softmax（验收载体）

```python
import tila


@tila.jit
def softmax(
    a: tila.Tensor[tila.float16, M, N],
    o: tila.Tensor[tila.float16, M, N],
    BM: tila.constexpr = 64,
    BN: tila.constexpr = 128,
):
    pid = tila.program_id(0)
    rm2 = tila.expand_dim(pid * BM + tila.arange(0, BM), 1)     # (BM, 1)  L0
    rn2 = tila.expand_dim(tila.arange(0, BN), 0)                # (1, BN)  L1
    m2 = (rm2 < M) & (rn2 < N)                                  # (BM, BN) Product(L0,L1)

    x = tila.cast(tila.load(a, (rm2, rn2), mask=m2), tila.float32)
    neg = tila.where(m2, x, tila.neg_inf)                       # 掩码列不进 max（零元哨兵）
    mx = tila.max(neg, axis=1)                                  # (BM,)    L0（边缘化）
    mx2 = tila.expand_dim(mx, 1)                                # (BM, 1)  L0
    e = tila.where(m2, tila.exp(x - mx2), 0.0)                  # (BM, BN) Product(L0,L1)
    s = tila.sum(e, axis=1)                                     # (BM,)    L0（边缘化）
    s2 = tila.expand_dim(s, 1)                                  # (BM, 1)  L0
    y = tila.where(m2, e / s2, 0.0)                             # 掩码行不产生 NaN（非严格：未选侧 NaN 不可观察）
    tila.store(o, (rm2, rn2), tila.cast(y, tila.float16), mask=m2)
```

要点：f16 进出、f32 内部（入口 cast，强类型不隐式提升）；单 tile 覆盖整行
（BN ≥ N，列掩码）——**N > BN 的 online softmax（running max）需要跨循环的
非 zeros 种子（max 的零元是 −∞），是 v0.4 围栏的既定推迟项**（§9）；
全掩码行/列的 `e/s2 = 0/0` 由末端 where 消除（dead lane 卫生，§5）。

**被拒的替代设计**：

| 方案 | 拒绝理由 |
|---|---|
| `keep_dims=True` 参数 | 复制 `expand_dim` 的既有职责，换一种隐式；丢轴 + 显式升维是更小的规则面 |
| 归约结果提升 f32（Triton `tl.max` 对 <32 位 dtype 的实际行为） | 隐式精度决策——与"无隐式收窄/无隐式提升"立场冲突；教程式"入口即 cast"是显式等价物。backend 侧的 Triton 提升由 lowering 显式抵消（§4） |
| `other=-inf` 的 load 掩码惯用法 | Tila 浮点字面量只有有限值——**正确解法是常量 `tila.neg_inf`（§1.3）而非扩字面量语法**；load 的 `other` 语义保持"用户提供的有限值"不变 |
| `−1e30` 有限哨兵（本稿初版方案，评审后撤回） | 依赖"真实数据 > −1e30"的隐式假设：f32 存储的合法输入（−3e38）会让哨兵污染 max，与 `torch.softmax` 的等价声明直接冲突 |
| `tl.dot(acc=…)` 直接融合累加 | v0.4 已裁定显式 `+=`（φ 通道单一、可围栏）；`acc=` 是 Triton 侧优化，Tila 表面不复制 |
| rank-1 全归约 → Scalar | 值位置新增"tile 退化的标量浮点"这条新值流；R6 起的比较前提（Tile 左部）等规则面都会被牵动（§9/§12）。注：Scalar **类型本身自 v0.1 已存在**（运行时标量参数）——拒绝的是"归约产生它"这条规则，类型层无缺口（评审 §19 的澄清，采纳） |
| sum/max 直接接受 Mma 输入 | 边缘化对 Mma 未定义（MMA 的行/列分布不是独立轴分布的积）；attention 的 `softmax(QK^T)` 需要"先物化再归约"或专用规则——v0.6 正题，现在放行等于无声拉伸桥接假说 |
| 归约进 K 循环内（跨迭代部分和的隐式融合） | v0.4 围栏已定：跨迭代只走显式 `+=`；tile 内归约 + 显式累加的组合已覆盖（`acc += tila.sum(t, 1)` 合法且自然） |
| 跨域语境定型（`x + 1` 当 f32、`x + 1.5` 当 i32） | R24 只做**同域**定型（float 字面量进 float 期望、int 字面量进 int 期望）；跨域是隐式转换，拒绝（§2.6） |

## 2. 类型层

### 2.1 R20 归约与边缘化（本设计的核心）

**形式化**（评审 §27 采纳）：对 rank-2 shape Σ = (d₀, d₁) 与布局
L ∈ Layout(Σ)，定义边缘化算子

```
marginal_k : Layout(Σ) → Layout(Σ∖k)        （k ∈ {0, 1}）
```

它把"被归约轴上的分布积分掉、幸存轴保留自身分布"。规则（三分支，
结果分类 Exact / Unknown——Convertible 为 v0.6 Mma 归约预留，当前无实例）：

```
marginal(L, Σ, k)：
  1. normalize(L) ≡ Product(L₀, L₁)   →   Exact(k=0 ? L₁ : L₀)
     （Product 是"独立坐标分布的笛卡尔复合"——v0.2 §3 语义；幸存轴的
       边缘分布恰是其自身因子。size-1 轴被归约时本式自动给出正确答案：
       平凡因子被丢弃，与边缘化一致）
  2. L 非 Product 且 Σ[k] ≡ 1         →   Exact(L)
     （被归约轴是长度 1 的轴——其分布平凡，R13 原则同款）
  3. 唯一非平凡轴被归约                →   Exact(Identity(()))
     （结果全平凡——与 broadcast_layout 的全 size-1 退化同款；实现期
       补上的第四情形：(64,1) 归约轴 0 → (1,)）
  4. L ≡ Zeros(Σ)                     →   Exact(Zeros(Σ∖k))
     （全同值的边缘分布仍是全同值——Zeros 种子对轴删除封闭；实现期
       补上：zeros tile 是合法归约操作数）
  5. 否则                              →   Unknown → E21 ReduceLayout
     （现实中 = Mma 输入：rank-2、双非平凡轴、非 Product 的唯一常见来源）
```

**Product-compatible**：布局 L 称为 Product-compatible，若 normalize(L)
是 Product 项或平凡（size-1 轴）。v0.5 的归约接受且仅接受
Product-compatible 操作数——"不 compatible 就没有语义规则"这句话把
E21 的性质说准了（评审 §4 采纳）：**E21 是"语义层边缘化未定义"，不是
"backend 做不到"**——未来 Mma 归约若落地，很可能是语义规则缺失而
backend 可 convert_layout 实现的 Convertible 情形，届时是 v0.6 的
新规则而非 E21 的改判。

```
Γ ⊢ x : Tile[dt, Σ, L]    rank(Σ) = 2    dt 具备对应能力（sum→'+'，max→'<'；E16）
axis ∈ {0, 1}（INT 字面量 / constexpr 特化值；E13）
────────────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.sum(x, axis=k) / tila.max(x, axis=k) : Tile[dt, Σ∖k, marginal(L, Σ, k).value]
```

- **为什么不引入 ReduceL term**：边缘化不是化简律而是构造规则——结果分布
  是输入分布的子项，直接构造（与 `strides_of` 同款"事实源"风格）；
  `origin_layout` 保存原始 L 供诊断。引入 `ReduceL(L, k)` + 新律是同一数学
  的更多机器（评审一致，§12.3 关闭）。
- **这是第一个"分布销毁型"运算**：dot 之前所有规则都保持或擦除分布；归约
  把分布砍掉一维。桥接含义：Tila 声称"幸存轴的语义分布不变"，而 Triton 的
  `tl.sum/tl.max` 涉及跨线程通信、结果 encoding 由它自己推断——**"边缘化
  预测"是否与 Triton 实测一致是 oracle 第二轮的实验命题**（§8.1，H2）。
- E21 的分工纪律：**E21 只管归约前提（rank、layout 边缘化未定义）**；dtype
  走 E16、axis 形态走 E13、（where 的）shape 走 E03——不做垃圾桶。

### 2.2 R21 一元数学（律 L8：元素逐位律）

```
Γ ⊢ x : Tile[dt, Σ, L]    dt ∈ UNARY 表该 op 的能力域（E16 否则）
────────────────────────────────────────────────────────────────────
Γ ⊢ tila.exp(x) : Tile[dt, Σ, normalize(L)]        （exp2 / sqrt / abs 同理）
```

```
(L8)  ElemL(L) ≡ L        # 逐元素一元运算不改变分布
```

- **L8 是记法、不是 IR term**（评审 §15 采纳）："逐元素运算不改变'谁持有
  哪个元素'"直接写进 R21 的结论（结果 layout = 操作数 layout 的正规形式），
  **不物化 `ElemL` 布局项**。与 CastL 的处置差异是刻意的：CastL 是 v0.1
  历史 term（当时代数尚小）；v0.5 起不再新增"永远 ≡ 恒等"的 term——
  代数项要携带信息，否则只是记账噪音。CastL/L3 的既有语义不变。
- 能力表（`arithmetic.py` 的 UNARY 表，机器可读）：

  | op | f16 | bf16 | f32 | f64 | int（i8–i64） | bool / fp8 |
  |---|---|---|---|---|---|---|
  | exp / exp2 / sqrt | ✓ | ✓ | ✓ | ✓ | E16 | E16 |
  | abs | ✓ | ✓ | ✓ | ✓ | ✓ | E16 |

### 2.3 R22 where（R14 的 n 元推广）

```
Γ ⊢ c : Tile[bool, Σc, Lc]
Γ ⊢ a : Tile[dt, Σa, La] | 字面量/neg_inf（R24 按 b 侧定型）   Γ ⊢ b : Tile[dt, Σb, Lb] | 字面量/neg_inf（R24 按 a 侧定型）
dt 两侧严格相等（E02；字面量经 R24 定型后参与该检查）
Σ = Σc ⊗ Σa ⊗ Σb 良式（E03）    a、b 不同为字面量（E13）
────────────────────────────────────────────────────────────────────────────────────
Γ ⊢ tila.where(c, a, b) : Tile[dt, Σ, merge_nontrivial((Lc,Σc), (La,Σa), (Lb,Σb))>
```

**merge_nontrivial 形式化**（评审 §9 采纳——v0.5 是第一次三方归并，
规则必须明说）：逐轴 j ——
若该轴上恰一侧 size ≠ 1：取该侧因子（广播侧平凡，R14 同款）；
若两侧 size ≠ 1（双侧非平凡）：**要求 equiv(L_left, L_right)，否则 E05**；
全平凡（都被广播）：`Identity(1)`。字面量/neg_inf 侧不携带分布（视作
BcastScalarL 平凡化，L2 擦除）。

- 实现即 **pairwise 折叠**：`merge(c,a)` 再 `merge(·,b)`，每步严格退化
  为 R14 的 `broadcast_layout`（shape E03 / layout E05 都来自既有机器），
  **规则不新**。
- cond 的 dtype 必须 bool（E02——掩码来自比较，与 R8/R10 同款纪律）。

### 2.4 R23 num_programs

```
axis 为字面量 / constexpr 特化值 ∈ {0, 1}（E13）
─────────────────────────────────────────────
Γ ⊢ tila.num_programs(axis) : Scalar(i32)
```

与 R1 对偶：R1 读"我在哪"，R23 读"总共多少"。发射 `tl.num_programs(axis)`。
**observational**（§1.4）：只读观测，不参与 launch 推断。

### 2.5 R24 语境字面量定型（Contextual Literal Typing；评审 §7 采纳）

```
e 为浮点字面量（含 tila.neg_inf）    Γ ⊢ 其它侧 : Tile[dt, …] / 期望 dtype dt    dt ∈ FLOAT
──────────────────────────────────────────────────────────────────────────────────────
e 定型为 Scalar(dt)（直接 elaboration，非 f64-再-隐式收窄）

e 为整数字面量    同款，dt ∈ INT
```

- **同域限定**：float 字面量只进 float 期望、int 字面量只进 int 期望；跨域
  （`x_f32 + 1`、`x_i32 + 1.5`）仍是 E02——语境定型是"字面量本无 dtype、
  语境赋予"，不是隐式转换的侧门。
- 语境来源（v0.5 全部）：**二元算术/比较**的 Tile 侧（R3/R4/R6 的字面量
  对手）；**where 的 a/b 分支**（互为期望，§2.3）。独立字面量（无语境）
  保持既有定型（int → i32；float → f64——`Scalar` 参数注解既有语义）；
  `tila.neg_inf` 独立出现定型 f32。
- 这是基础设施规则：`zeros` 的显式 dtype、`where` 的哨兵分支、未来的
  `full`/更多内建都消费它（评审 §25 原语 5）。

### 2.6 轨迹闭环律 L9 与桥接假说 H2（intended，非定理）

softmax 数据流的 layout 轨迹（§2.7 走查）形成闭环：

```
Product(L_r, L_c) ──reduce_c──▶ L_r ──expand_c──▶ (rank-2 平凡因子) ──broadcast──▶ Product(L_r, L_c)
```

**L9（intended semantic law；oracle 第二轮已获 concrete 佐证，§8.1）**：

```
expand_k(marginal_k(L)) ≡ L        （对 Product-compatible L）
```

即"边缘化取因子、广播还原因子"恒等往返。配套**桥接假说 H2**（H1——v0.2
MMA 家族分离——的延伸）：

> **强形式**：Triton 对 Product 族的 `tl.sum/tl.max` 结果 encoding 与
> 独立构造的幸存轴 tile encoding 同族，无 convert 发生。
> **弱形式（可接受降级）**：结果 encoding 不同族，但单次 `convert_layout`
> 即可到达语义等价的分布——Tila 抽象引入显式 realize/convert 层。
> **证伪**：两者皆不成立——marginal 降级为"语义声明 + 桥接层显式转换"，
> 表面语言不变（§8.1 预案）。

**H2 实验判定（2026-08-24 实测，triton-windows 3.7.1 / TITAN Xp，32/32
组合一致，`layout-oracle-notes.md` 第二轮）**：

- **强形式证伪**：reduce 结果 encoding 恒为
  `#ttg.slice<{dim = k, parent = #blocked_input}>`——**输入分布的切片**，
  不是独立 1D 构造的 blocked 族；
- **弱形式成立且升级**：softmax 形状轨迹（load → reduce → expand →
  逐元素 → store）**0 次 convert_layout**（全部组合）；
- **L9 的 concrete 逐字实现**：`expand_dims(slice, k)` 的结果 layout 直接
  返回 parent——"边缘化取因子、升维还原因子"在 TTGIR 层就是恒等往返；
- 结果与新构造的幸存轴 tile（如 `tl.arange(0,64)` 派生值）相遇时，
  Triton 按需插入**单次** convert_layout——Tila 语义等价声明（结果分布
  = 幸存轴自身分布）与之相容。

这正是 H1 的结局模式重演：**强形式证伪、家族级（语义级）成立**——而且
证伪的方式比预期更有利：slice-of-parent 就是"幸存轴继承其在复合分布中
的位置"的字面具体化，Tila 的 Product-因子语义声明是它的语义影子。
marginal 规则照 §2.1 原样实现，不降级。

### 2.7 softmax 类型走查（BM=64, BN=128 特化；L0/L1/L2 为元变量名）

| 语句 | 规则 | 类型 | layout |
|---|---|---|---|
| `x = cast(load(a,(rm2,rn2),…), f32)` | R8+R11 | `Tile<f32,(64,128),L2>` | `L2 = product(L0,L1)`（坐标广播积） |
| `neg = where(m2, x, neg_inf)` | R22+R24 | `Tile<f32,(64,128),L2>` | 三方归并：cond 侧 L2、常量侧平凡 → L2；neg_inf 定型 f32 |
| `mx = max(neg, axis=1)` | **R20 边缘化** | `Tile<f32,(64,),L0>` | `marginal(product(L0,L1), 1) = L0` |
| `mx2 = expand_dim(mx, 1)` | R13 | `Tile<f32,(64,1),L0>` | 不变（size-1 轴平凡） |
| `e = where(m2, exp(x − mx2), 0.0)` | R21+R14+R22+R24 | `Tile<f32,(64,128),L2>` | `exp` 保序（L8）；`−` 归并 → L2；where → L2；`0.0` 定型 f32 |
| `s = sum(e, axis=1)` | **R20** | `Tile<f32,(64,),L0>` | 边缘化 → L0 |
| `s2 = expand_dim(s, 1)` | R13 | `Tile<f32,(64,1),L0>` | L0 |
| `y = where(m2, e / s2, 0.0)` | R5(`/`)+R22+R24 | `Tile<f32,(64,128),L2>` | `⊗` 归并 → L2 |
| `store(o, (rm2,rn2), cast(y,f16), …)` | R9' | `()` | 内存边界布局无关 |

**整个数据流的 layout 轨迹在 Product 族内闭环**（L9 的走查证明）——
边缘化取因子、广播/归并还原因子、逐元素保持：没有任何一步需要"分布
转换"。这是本设计不变量的走查证明。

## 3. TIR

```
TReduce:      op: str                 # "sum" | "max"
              tile: str, axis: int    # opcode: sum / max（axis 已特化字面量）
TElem:        op: str                 # "exp" | "exp2" | "sqrt" | "abs"
              operand: str            # opcode 即 op 名
TWhere:       cond: str, a: str, b: str
TNumPrograms: axis: int
```

- dump（house 格式）：

```
%mx = max %t3 1 : Tile<f32, (64,), L0> [#mx]
%s  = sum %e 1 : Tile<f32, (64,), L0> [#s]
%e  = exp %t5 : Tile<f32, (64,128), L2> [#e]
%w  = where %m2 %x %t7 : Tile<f32, (64,128), L2> [#w]
%np = num_programs 0 : Scalar(i32) [#np]
```

- 无 region、无新结构——四条都是普通值指令；`_finalize_ids` / printer 的
  操作数遍历按既定模式加分支（机械）。
- 字面量/neg_inf 分支按既有字面量指令模式（`TConstFloat`）物化为值 id
  （dtype 由 R24 语境定型，随指令携带）；`−inf` 的 dump 拼写为 `-inf`。
- 归约与循环组合的合法性由类型自然给出：`acc += tila.sum(t, 1)` 中
  sum 结果是普通 Tile（Zeros 种子 ⊕ 边缘化分布走 L7 物化）——无需任何
  新交互规则（测试覆盖）。

## 4. Triton lowering

| TIR | Triton |
|---|---|
| `TReduce(sum, x, k)` | `tl.sum(<x>, k, dtype=<D>)`——**dtype 恒显式**（D = Tila 结果 dtype；实测 3.7.1 有此形参，且其默认策略 int<32 → i32/u32） |
| `TReduce(max, x, k)` | bitwidth(D) ≥ 32：`tl.max(<x>, k)`；否则 `tl.cast(tl.max(<x>, k), <D>)`（实测 3.7.1 对 <32 位 dtype 内部提升 f32/i32 **并以提升后 dtype 返回**——cast 恢复 Tila dtype；max 无舍入，恢复无损） |
| `TElem(op, x)` | abs：`tl.abs(<x>)`；exp/exp2/sqrt 且 dtype ∈ f32/f64：`tl.<op>(<x>)`；f16/bf16：`tl.cast(tl.<op>(tl.cast(<x>, tl.float32)), <D>)`——实测 3.7.1 数学一元**只接受 fp32/fp64**（语义层拒绝 f16/bf16），f32 计算 + cast 恢复（numpy 对 f16 ufunc 同款内部升精度） |
| `TWhere(c, a, b)` | `tl.where(<c>, <a>, <b>)`（字面量按既有字面量发射；`neg_inf` → `float("-inf")`） |
| `TNumPrograms(k)` | `tl.num_programs(k)` |

- **适配原则**（评审 §5/§26① 采纳）：Triton backend 是 Tila 语义的
  **实现**，不是 Triton 默认策略的**继承者**——凡 Triton 归约有自由度的
  地方（dtype），lowering 显式钉死。累加精度 = D 一并由 `dtype=` 钉住。
- 全部一阶映射，无展开、无策略。
- launcher：**零改动**（无新参数类别、无新断言、grid 推导不涉 num_programs）。
- 生成的 softmax kernel 体即 §1.5 的逐行同构（黄金快照）。

## 5. Interpreter

- `sum`：`np.sum(x, axis=k, dtype=D)`——**dtype 显式**（numpy 对 int<32
  默认提升平台整数宽度，与 Triton 同款陷阱；评审 §5 提到的 interpreter
  dtype 漂移问题在自有 interpreter 以显式 dtype 消灭）。
- `max`：`np.max(x, axis=k)` 后 `.astype(D)` 钉住（对 <32 位 dtype 与
  lowering 的 cast-恢复两侧对齐）。
- `exp/exp2/sqrt/abs`：`np.exp / np.exp2 / np.sqrt / np.abs`（ml_dtypes
  覆盖 bf16），dtype 保持同款。
- `where`：`np.where`（字面量分支按 R24 定型的 dtype 构造标量；两侧都
  求值——非严格语义允许，未选侧现象不可观察）。
- **浮点异常不可观察**：整个执行包 `np.errstate(all='ignore')`——
  `0/0 → NaN`、f16 exp 溢出等 dead-lane/未选侧现象与 where 的值选择
  语义配套（§1.3 非严格句的 interpreter 对应物；GPU 侧本就如此）。
- `neg_inf`：按定型 dtype 构造（`np.finfo(D).min` 的 next——即 −inf；
  f32/f64 用 `float("-inf")`，f16/bf16 用 `ml_dtypes` 的 −inf）。
- `num_programs`：从 launch plan 推导的 grid 维读取（`len` 已知；未建立
  轴 = 1，与 Triton 补 1 语义对齐）。
